## 1. 결정 사항 (2026-11-06)

시안과 기존 확정 결정(검토 문서 7.4·8.4·CMN-01)이 달라 사용자가 항목별로 직접 결정했다.

| ID | 항목 | 기존 결정 | 결정 | 영향 |
|---|---|---|---|---|
| S-09 | 주 동작 색 | 주 동작 = 파랑, 분홍 = 브랜드 강조 | **주 동작 = 분홍.** 흰 글자 대비 4.5:1을 위해 pink-600(`#C4457B`)·pink-700을 쓴다. 시안 버튼(`#E54C8A` 등)보다 조금 진하다. 포커스도 분홍, 링크·보조 강조는 보라(lavender-700) | `primary`·`focus`·`selected` 토큰 값 변경, `link`·`accent-soft` 토큰 추가. 오류(빨강)와는 아이콘·문구로 구분한다 |
| S-10 | 배경·면 | 흰 배경, 카드 그림자 없음(테두리만), 그림자는 떠 있는 요소 전용 | **시안 톤 채택, 범위 제한.** 파스텔 그라데이션 바탕과 물결 장식은 레이아웃 바탕(인증 레이아웃·앱 틀) 한 곳에만 둔다. 카드·패널은 흰 면 + 부드러운 그림자(`shadow-card`). 반투명 유리 효과(블러)는 쓰지 않는다 | `canvas-*` 색, `shadow-card`·`shadow-primary`, `radius-2xl` 토큰 추가 |
| S-11 | 메뉴 배치 | 태블릿 88px 레일, 휴대폰 하단 탭 바 | **폭에 따라 세 가지.** `tablet-lg`(960 이상)는 시안처럼 폭 240 사이드바(로고·메뉴 가로 배치·계정), `tablet`(600~959)은 88px 레일, 휴대폰은 하단 탭 바 | `spacing-rail`(88)·`spacing-sidebar`(240) 토큰 추가. CMN-01 수정 |
| S-12 | 일러스트·로고 | (정하지 않음) | **단순화 SVG 직접 제작.** 시안 구도와 CI 색을 따른 평면·약한 입체 SVG를 만들고, 디자이너 원본을 받으면 같은 자리에서 교체한다. 로고는 원본을 받을 때까지 글자 로고(DOWN 파랑 / FORCE 분홍→보라) | 일러스트를 React 컴포넌트(SVG)로 둔다. S-02 로고 원본 확보는 남은 확인으로 유지 |

## 2. 시안 분석

### 2.1 톤 특징

| 구분 | 시안의 모습 | 적용 방식 |
|---|---|---|
| 바탕 | 연보라→연분홍 대각선 그라데이션, 화면 가장자리에 분홍·보라·하늘색 물결 | `AppCanvas` 한 곳에서 처리 (4장) |
| 면 | 흰색에 가까운 카드, 옅은 흰 테두리, 넓게 퍼진 옅은 그림자 | `Card`·`Panel`: `bg-bg` + `shadow-card` |
| 모양 | 큰 패널 모서리 약 24, 카드 약 20, 주요 버튼·입력란·칩은 알약형 | `rounded-2xl`·`rounded-xl`·`rounded-full` |
| 주 동작 | 분홍 버튼. 대표 동작(새 회의)은 분홍 그라데이션 + 분홍 빛 번짐 | `Button` `primary`·`hero` |
| 강조 | 선택된 메뉴: 연분홍 면 + 분홍 글자. AI·남은 시도: 연보라 알약 | `selected`, `accent-soft` |
| 장식 | 음성 파형(파랑·분홍·보라), AI 배지, 반짝임, 체크 문서 | 일러스트 컴포넌트 (S-12) |
| 글자 | 진한 남색 계열 제목, 굵은 제목과 보통 본문 대비가 큼 | `text-text`(neutral-900)로 통일. 시안의 남색(`#041037`)은 쓰지 않는다 |
| 아이콘 | 2px 안팎 선 아이콘, 둥근 끝 | 아이콘 방식은 1단계에서 결정 (6장) |

### 2.2 측정 색 (이미지 픽셀 추출)

이미지에서 직접 뽑은 값이라 압축·안티앨리어싱 오차가 있다. 대비는 WCAG 2.2 공식으로 계산했다.

| 위치 | 시안 값 | 흰 글자(또는 흰 배경) 대비 | 판정 | 적용 토큰 |
|---|---|---|---|---|
| AUTH-02 확인 버튼 | `#E54C8A` | 3.66:1 | 미달(4.5) | `primary` pink-600 `#C4457B` 4.68:1 |
| AUTH-01 화살표 버튼 | `#ED5699` | 3.29:1 | 미달 | `primary` |
| HOME 새 회의 버튼 | `#F973B6`→`#F4529C` | 2.57~3.21:1 | 미달 | 그라데이션 pink-600→pink-700 (4.68~6.79:1) |
| AUTH-02 남은 시간 숫자 | `#EB287E` | 4.09:1 | 미달 | `brand-text` pink-700 6.79:1 |
| HOME 선택 메뉴 글자 | `#E80366` | 4.53:1 | 통과 | `selected-text` pink-800 |
| HOME 전체 보기 링크 | `#605692` | 6.47:1 | 통과 | `link` lavender-700 6.64:1 |
| AUTH-02 남은 시도 숫자 | `#483D8E` | 9.00:1 | 통과 | `accent-soft-text` lavender-800 |
| 제목 글자 | `#041037` | 18.51:1 | 통과 | `text` neutral-900 |
| 바탕 | `#FDF5FE`~`#FBE8FE` | - | - | `canvas-start/mid/end` |
| 입력란 테두리 | 아주 옅음 | 3:1 미만 (추정) | 미달 | `border-input` neutral-500 (바탕 위 3.68:1) |

**결론:** 시안의 분홍 버튼과 입력 테두리는 그대로 쓰면 AA를 충족하지 못한다. 색상 계열은 유지하고 밝기만 진하게 맞췄다. 화면 결과물은 시안보다 버튼이 약간 진하고 입력 테두리가 조금 더 또렷하다. 이 두 가지는 의도된 차이다.

## 3. 톤 → 토큰

### 3.1 색 역할 (S-09)

| 색 | 역할 |
|---|---|
| 분홍 | 주 동작(버튼·포커스), 선택된 메뉴, 브랜드 강조, 녹음 표시 |
| 보라 | 링크·텍스트 버튼, 보조 정보 알약, AI 표시, 태그 |
| 파랑 | 로고 "DOWN", 일러스트·음성 파형 장식. 동작 색으로 쓰지 않는다 |
| 빨강·초록·주황 | 오류·성공·경고. 분홍 주 동작과 혼동되지 않게 항상 아이콘·문구를 함께 쓴다 |

### 3.2 용도별 토큰과 대비 검증

바탕 그라데이션의 가장 진한 색(pink-100 `#FEE8EE`) 위에서도 기준을 넘는지 함께 계산했다.

| 토큰 | 값 | 사용처 | 흰 배경 대비 | 바탕(pink-100) 대비 | 판정 |
|---|---|---|---|---|---|
| `primary` | pink-600 `#C4457B` | 주 버튼 배경 (흰 글자) | 흰 글자 4.68:1 | - | 통과 |
| `primary-hover` | pink-700 `#9B3661` | 주 버튼 눌림, 그라데이션 끝 | 흰 글자 6.79:1 | - | 통과 |
| `primary-soft` / `-text` | pink-50 / pink-800 | 약한 주 동작 버튼, 안내 배너 | 9.11:1 (pink-50 위) | - | 통과 |
| `bg-subtle` / `text-muted` | neutral-50 / neutral-600 | 중립 알약(`Pill` neutral) | 6.01:1 (neutral-50 위) | - | 통과 |
| `danger` 눌림 | red-700 + 흰 글자 | 삭제 버튼 눌린 상태 | 흰 글자 6.81:1 | - | 통과 |
| `focus` | pink-600 | 키보드 포커스 표시 | 4.68:1 | 4.01:1 | 통과 (3:1) |
| `link` | lavender-700 `#674F9A` | 링크, 텍스트 버튼 | 6.64:1 | 5.69:1 | 통과 |
| `selected` / `-text` | pink-100 / pink-800 `#742848` | 선택된 메뉴·탭·행 | - | 8.41:1 | 통과 |
| `brand-text` | pink-700 | 분홍 강조 글자(타이머 등) | 6.79:1 | 5.81:1 | 통과 |
| `accent-soft` / `-text` | lavender-100 / lavender-800 `#4D3B74` | 정보 알약, AI 배지, 태그 | - | 8.22:1 (lavender-100 위) | 통과 |

| `border-input` | neutral-500 | 입력란 테두리 | 4.29:1 | 3.68:1 | 통과 (3:1) |
| `danger` | red-600 | 삭제·종료 버튼 | 흰 글자 4.72:1 | - | 통과 |
| (비활성) | neutral-400 | 비활성 글자 | 2.49:1 | - | 대비 예외. `aria-disabled`·문구로도 알림 |

- 대비 기준 대상은 흰 카드 면과 바탕 그라데이션 두 가지다. 반투명 면을 겹치면 다시 계산해야 하므로 반투명 면 위 글자는 피한다.
- 로고 글자(그라데이션)는 로고라 대비 기준 예외다.

### 3.3 면·그림자·모서리 (S-10)

| 요소 | 토큰 | 규칙 |

## 4. 공통 컴포넌트 (1단계에서 만들 목록)

화면에서 클래스 문자열을 복사하지 않도록 아래 컴포넌트에 시안 톤을 담는다. 모든 컴포넌트는 Tailwind만 쓴다. 포커스 표시는 진입 파일 기본 규칙(`focus` 색 2px 외곽선, #5 결정)을 따르고 다른 모양이 필요할 때만 덮어쓴다. 비활성 표시는 컴포넌트에서 직접 지정한다(`CLAUDE.md`). 아이콘은 `lucide-react`를 공통 `Icon`으로 감싸 쓴다.

| `AuthLayout` | AUTH-01·02. `tablet-lg`: 왼쪽 일러스트, 오른쪽 입력 영역(최대 폭 `max-w-auth`), 왼쪽 위 로고. `tablet`: 1단, 일러스트를 입력 영역 위에 작게. 휴대폰: 1단, 일러스트 숨김 또는 작게. `short`: 일러스트·로고 숨김 |
| `AppShell` | 3.4의 탭 바·레일·사이드바 + 상단 바 + 본문(최대 폭 `max-w-content`) |
| `TopBar` | 왼쪽 페이지 제목(`headline`), 오른쪽 문서 연결 상태 칩(흰 알약 + `shadow-card` + 상태 점 + 문구). 안전 영역 반영 |
| `NavItem` | 선택 시 `bg-selected text-selected-text`(시안: 연분홍 면 + 분홍 글자) + `aria-current="page"` |

## 5. 화면별 시안과 기획 차이

시안과 화면 기획 문서가 다른 부분의 처리안이다. "기본 처리"는 이 문서에서 정한 값이고, "확인 필요"는 해당 묶음 착수 전에 정한다.

### 5.1 AUTH-01 로그인 (이메일 입력)

| 항목 | 시안 | 기획 | 기본 처리 |
|---|---|---|---|
| 배치 | 바탕 위 2단(왼쪽 일러스트, 오른쪽 입력), 카드 없음 | 흰 배경 가운데 카드 | 시안 배치. `AuthLayout` |
| 이름표 | 입력란 안 예시 글자만 | 이름표 있음 | 입력란 위에 보이는 이름표("회사 이메일")를 둔다. 예시 글자만으로는 입력 중 안내가 사라진다(WCAG 3.3.2) |
| 제목 | 없음 | 있음 | 보이는 제목을 둔다(`headline`, 문구는 R-09 용어 결정 때). 화면 읽기 프로그램에 화면 목적을 알리기 위해서다 |
| 실행 버튼 | 원형 화살표만 | 버튼 | `IconButton` 주 동작형 64, `aria-label` 필수 |
| 메일 설정(F07) | 없음 | 미설정 시 "메일 설정" 버튼 | 입력 아래 `secondary` 버튼, 미설정일 때만 표시 |
| 오류·도메인 안내 | 없음 | 있음 | 입력 아래 `caption` + 아이콘 |

### 5.2 AUTH-02 인증 코드 입력

| 항목 | 시안 | 기획 | 기본 처리 |
|---|---|---|---|
| 배치 | 2단, 카드 없음 | 가운데 카드 | 시안 배치. `AuthLayout` |
| 제목 아이콘 | 방패 아이콘(연분홍 면) | 없음 | 시안대로. 장식이므로 `aria-hidden` |
| 이메일 변경 | 오른쪽 알약 버튼 | 텍스트 버튼 | 시안대로 `secondary` `sm` 알약 |
| 남은 시간 | 분홍 숫자 + 진행 막대 | `caption` 숫자 | 시안대로 막대 추가. 숫자 `brand-text`, 1분 미만 `danger-text` + 아이콘(기획 유지) |
| 남은 시도 | 항상 보이는 보라 알약 | 오류 시 표시 | 시안대로 항상 표시(`Pill`) |
| 코드 다시 받기 | 폭 가득 테두리 버튼, 대기 중 흐림 | 텍스트 버튼 | 시안대로 `secondary` 폭 가득, 대기 중 비활성 표시 |

### 5.3 HOME-01 메인 + CMN-01 앱 틀

| 항목 | 시안 | 기획 | 기본 처리 |
|---|---|---|---|
| 메뉴 | 넓은 사이드바 | 88px 레일 | S-11 (폭에 따라 세 가지) |
| 인사 문구 | 없음 (상단 제목 "홈") | "안녕하세요, …님" 제안 | 시안대로 넣지 않는다 |

| 계정 | 사이드바 아래 이메일 + 로그아웃 직접 노출 | 사용자 메뉴 | 사이드바(`tablet-lg`)는 시안대로 직접 노출, 레일·휴대폰은 메뉴. 로그아웃은 둘 다 CMN-01-P02 확인 |

### 5.4 시안이 없는 화면

문서 연결(CMN-04, SET-02~06), MTG, MIN, PTC, SET-01은 시안이 없다. 4장 공통 컴포넌트와 `AppShell`을 조합해 같은 톤을 낸다. 화면 기획 문서의 색 표기 중 다음은 이 문서 기준으로 읽는다(각 묶음 착수 때 해당 문서를 고친다).

| 기획 문서 표기 | 이 문서 기준 |
|---|---|
| `primary`(파랑 blue-600) | `primary`(분홍 pink-600) |
| 링크 색 `primary-hover` | `link`(lavender-700) |
| `selected`(보라 계열) | `selected`(분홍 pink-100 면) |

## 7. 시안 톤 유지 확인 방법

- **시안 대조:** 시안이 있는 화면은 태블릿 가로(1180×820)로 화면을 찍어 시안 이미지와 나란히 놓고 배치·면·색 계열을 비교한다. 2.2의 의도된 차이(버튼 진하기, 입력 테두리)는 차이로 보지 않는다.
- **토큰 검사:** 임의값·기본 색은 `npm run lint`가 막는다. 시안 색(`#E54C8A` 등)을 직접 쓰지 않는다.
- **대비 검사:** 새 색 조합을 쓰면 3.2 표에 추가하고 흰 면과 바탕(pink-100) 두 곳에서 계산한다.
- **시안 없는 화면:** 착수 전에 4장 컴포넌트만으로 만들 수 있는지 확인한다. 새 모양이 필요하면 화면에 직접 만들지 않고 공통 컴포넌트에 추가한다.
