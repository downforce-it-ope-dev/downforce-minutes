# SET-01 설정

| 항목 | 내용 |
|---|---|
| 화면 ID | SET-01 |
| 유형 | 페이지 (설정 카드 모음) |
| 경로 | `/settings` |
| 현재 구현 | `frontend/src/SettingsPage.tsx`, `settingsApi.ts`, `emailSettingsApi.ts`, `slackSettingsApi.ts`, `emailSettingsStorage.ts`, `slackWebhookStorage.ts` |
| 진입 조건 | 로그인(신규). 관리자 제한 여부 D-05 |
| 연결 화면 | 문서 연결 설정 → SET-02 |
| 사용 API | API-001 앱 설정, API-019 연동 상태, API-035 Gmail 설정 조회·저장·삭제, API-036 Gmail 연결 시험, API-038 Slack 설정 조회·저장·삭제, API-039 Slack 시험 발송 |
| 현행 캡처 | [설정 화면](<../현_UI/설정 화면.png>) |

## 1. 화면 개요

회의록 저장(문서 서비스), 이메일 전달(Gmail), 알림(Slack) 연동 상태를 확인하고 설정한다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| SET-01-F01 | 문서 연결 요약 | 연결 서비스와 상태 | "{서비스}에 회의록과 기본 템플릿을 저장합니다." + 문서 연결 설정(SET-02) |
| SET-01-F02 | 이메일 설정 입력 | 발신 주소, Google 클라이언트 ID, 클라이언트 보안 키, 연결 토큰(Refresh Token) | 4개 모두 필수. 비밀값은 비밀번호 입력란 |
| SET-01-F03 | 이메일 저장·연결 확인 | 저장 후 자동 연결 시험 | 저장(API-035 PUT) → 시험(API-036). 시험 실패 시 오류 표시, 저장값은 유지 |
| SET-01-F04 | 이메일 설정 보기·수정·삭제 | 설정 완료 시 마스킹 표시 | 수정 → 빈 입력란으로 다시 입력, 취소 가능. 삭제 |
| SET-01-F05 | Slack 설정 | Incoming Webhook 주소 | 저장(API-038 PUT) → 시험 발송(API-039). 설정 완료 시 마스킹 + 수정·삭제 |
| SET-01-F06 | 상태 배지 | 서비스별 연결 상태 | 아래 상태 문구 표 |
| SET-01-F07 | 전체 새로고침 | 모든 연결 상태 다시 조회 | API-001 + API-019 |
| SET-01-F08 | 브라우저 복구 | 서버 설정이 비어 있으면 브라우저에 보관한 값으로 복원 | 현행: 앱 시작 시 실행 (D-09) |
| SET-01-F09 | 시험 메일 발송 | 발신 주소로 시험 메일 | **제안**: API-037은 있으나 화면에서 사용하지 않음 |

### 상태 문구 (현행)

| 상태 | 문구 |
|---|---|
| 정상 | 연결 상태 확인됨(문서) / 연결 확인됨(이메일·알림) |
| 미선택 | 문서 서비스를 선택해 연결할 수 있습니다. |
| 미설정 | 설정 확인이 필요합니다. |
| 연결 불가 | 연결 상태를 확인하지 못했습니다. |
| 구조 접근 불가 | 서비스 연결은 확인했지만 필수 Meetings 또는 Participants 구조에 접근할 수 없습니다. |
| 알림 미확인 | 최근 알림 전달 상태가 확인되지 않았습니다. |
| 조회 실패 | 연결 상태를 불러오지 못했습니다. |

## 4. 상태별 화면

| 상태 | 표시 |
|---|---|
| 상태 조회 중 | "연결 상태를 불러오는 중…" |
| 둘 다 조회 실패 | "설정과 연결 상태를 불러오지 못했습니다." + 전체 다시 불러오기 |
| 일부 조회 실패 | 확인 가능한 정보 표시 + 경고 + 다시 확인 |
| 이메일·Slack 불러오는 중 | 카드 안 "…설정을 불러오는 중…" |
| 저장·시험 실패 | 카드 안 오류 문구 |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)**
  - Google OAuth 클라이언트 ID·보안 키·Refresh Token을 일반 사용자 화면에 그대로 요구한다. 용어가 어렵고 발급 방법 안내가 없다.
  - 삭제 버튼에 확인 단계가 없다.
  - 저장 버튼이 보조 스타일이라 주 행동이 드러나지 않는다(캡처).
- **보안 관련 사실 (코드 확인)** — Gmail 설정값(클라이언트 보안 키, 연결 토큰 포함)과 Slack Webhook 주소를 브라우저 `localStorage`에 평문으로 저장하고, 앱 시작 시 서버 설정이 비어 있으면 이 값으로 다시 저장한다(`emailSettingsStorage.ts`, `slackWebhookStorage.ts`, `App.tsx`). 로그인 도입 후 공용 PC 사용을 고려하면 유지 여부를 결정해야 한다(D-09).
- **제안**
  - 이메일 카드는 발신 주소만 기본 노출하고 OAuth 정보는 "고급" 접힘 영역 + 발급 안내 링크
  - 시험 메일 보내기(API-037), 삭제 확인 팝업 추가
  - 관리자 전용 메뉴로 분리 (D-05)
- **확인 필요** — D-03: 로그인 OTP 메일을 이 Gmail 설정으로 보낼지 여부. D-05, D-09.
