## 1. 화면 개요

문서 서비스에 Meeting Automation 문서 구조(Meetings, Participants, Meeting Data, Templates)를 만드는 작업, 또는 서비스 전환 작업의 진행과 결과를 보여 준다. 실패하면 재개하거나 종료할 수 있다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| SET-05-F01 | 진행 단계 | 연결 확인 → 문서 생성 → 생성 완료 | 연결 확인은 항상 완료 표시 |
| SET-05-F02 | 페이지 생성 진행 | Meeting Automation, Meetings, Participants, Meeting Data, Templates | 문서 생성 단계에서 페이지별 생성 완료·생성 중·대기 중 |
| SET-05-F03 | 진행 문구 | 현재 작업 설명 | 예: "Notion에 Meetings 페이지를 생성하고 있습니다." |
| SET-05-F04 | 자동 갱신 | 진행 중이면 약 1.8초 간격 조회 | 완료·실패 등 종료 상태가 되면 중지. 종료 상태에서는 화면 복귀 시 재조회 |
| SET-05-F05 | 완료 처리 | 완료 후 연결 정보 저장, 설정·참석자 재조회 | 성공 Toast "문서 서비스 연결이 준비되었습니다." + 확인 → HOME-01 |
| SET-05-F06 | 작업 재개 | 실패·중단 시 | 서버가 `RETRY`를 허용할 때만 |
| SET-05-F07 | 작업 종료(취소) | 중단된 작업 정리 | 초기화 작업: "중단된 연결 작업 종료" → 입력 초기화 후 다시 연결 안내 |
| SET-05-F08 | 진행 상태 새로고침 | 수동 조회 | - |
| SET-05-F09 | 조회 실패 복구 | 상세 조회 실패 시 | "진행 상태 다시 불러오기", "연결 작업 종료 후 다시 연결". 서버 작업이 계속될 수 있으므로 새 작업은 보내지 않음 |
| SET-05-F10 | 결과 불명확 처리 | 시작 요청 결과를 모를 때 | "요청 상태 확인" 카드 + 다시 확인 |
| SET-05-F11 | 전환 진행 표시 | SWITCH 작업 | 참석자 n/m명 · 회의 n/m건 복사, 재개·취소 |

### 작업 상태 (현행)

| 상태 | 제목 | 안내 |
|---|---|---|
| 진행 중 (PENDING·RUNNING) | {서비스} 문서를 생성하고 있습니다 | 단계별 진행 |
| 완료 (SUCCEEDED) | 문서 연결 완료 | Meeting Automation 아래 Meetings, Participants, Meeting Data, Templates 페이지를 만들고 Templates에 기본 회의록을 넣었습니다. |
| 실패 (FAILED) | 문서 구조 준비 실패 | 재개 가능하면 재개 안내, 아니면 작업 ID·오류 코드를 관리자에게 전달 안내 |
| 중단 (INTERRUPTED) | 문서 구조 준비 중단 | 일부 페이지가 생성됐을 수 있으니 확인 후 재개 또는 종료 |
| 확인 필요 (RECONCILIATION_REQUIRED) | Provider 상태 확인 필요 | 생성된 페이지 확인 후 재개 또는 종료. 자동으로 새 페이지를 만들지 않음 |
| 취소 (CANCELLED) | 문서 구조 준비 취소 | - |

## 3. 화면 구성 요소

크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4·8장을 따른다. 문서 연결 진행 화면이므로 CMN-01 "집중 모드"(메뉴 숨김, 상단 바 제목만)로 표시한다. 마법사 열 폭은 SET-03 3.2를 따른다.

### 3.1 태블릿 (기준, 600px 이상)

```
┌──────────────────────────────────────────────────────────────┐
│ 문서 서비스 연결                                                │  상단 바 64px (제목만)
├──────────────────────────────────────────────────────────────┤
│        ┌ Notion 문서를 생성하고 있습니다 ─────────────────┐       │
│        │ (N) 문서 서비스에 연결 중  ◌                      │       │
│        │                                              │       │
│        │ ✓ ① 연결 확인                                  │       │  세로 단계 표시
│        │ ● ② 문서 생성                                  │       │
│        │    ✓ Meeting Automation      생성 완료          │       │  1줄 행 60
│        │    ✓ Meetings                생성 완료          │       │
│        │    ◌ Participants            생성 중            │       │
│        │    ○ Meeting Data            대기 중            │       │
│        │    ○ Templates               대기 중            │       │
│        │ ○ ③ 생성 완료                                  │       │
│        │                                              │       │
│        │ Notion에 Participants 페이지를 생성하고 있습니다.    │       │  진행 문구
│        └──────────────────────────────────────────────┘       │
│                                  [진행 상태 새로고침]            │
└──────────────────────────────────────────────────────────────┘
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 바 (64px) | 제목·설명 | 제목 | 문서 서비스 연결. `headline` |
| 진행 카드 | 카드 | 카드 | 테두리 `border`, `radius-lg`, 안쪽 여백 24(휴대폰 16) |
| | 카드 제목 | 제목 | 상태별 제목. `title` |
| | 서비스 표시 | 아이콘 + 텍스트 + 스피너 | "문서 서비스에 연결 중" / "연결 및 기본 구조 생성 완료". 스피너 색 `primary` |
| | 단계 표시 | 세로 단계 표시기 | 3단계, 완료 ✓·진행 번호 강조. 현재 단계 `primary`, 완료 ✓ 아이콘. 색만으로 구분하지 않는다 |
| | 페이지 생성 목록 | 목록 | 5개 페이지별 상태. 1줄 목록 행 56/60, 페이지 이름(`body`) + 상태 아이콘·문구(`caption`). 표시 전용이라 누르는 대상이 아니다 |
| | 진행 문구 | 상태 텍스트 | 스크린리더 실시간 알림. `body`, `text-muted` |
| | 전환 진행 (F11) | 텍스트 + 진행 막대 | 참석자 n/m명 · 회의 n/m건. 숫자는 고정폭 숫자. 진행 막대 색 `primary`. **확인 필요** — 진행 막대 높이는 8장에 정의가 없다(제안: 8) |
| | 확인 | 주 버튼 `lg` 56 | 완료 시 → HOME-01. `primary` |
| 실패 카드 | 머리 | 안내 상자 | 실패·중단·확인 필요 상태는 `danger-soft`(실패) 또는 `warning-soft`(중단·확인 필요) + 아이콘(제안). 취소는 중립(`bg-subtle`) |
| | 제목, 단계·상태, 작업 ID, 오류 코드 | 텍스트 | 현행은 그대로 노출. 제안(5장): 작업 ID·오류 코드는 "자세히 보기" 접힘(머리 행 56/60) 안으로, 작업 ID 복사 아이콘 버튼 48 |
| | 안내 | 텍스트 | 상태별 안내. `body` |
| | 작업 재개 / 중단된 연결 작업 종료 / 진행 상태 새로고침 | 버튼 | 허용된 행동만. 모두 높이 48 이상으로 크기를 맞추고(5장 현행 문제), 위계는 버튼 스타일(채움·보조)로 나눈다: 재개 = 주 버튼(`primary`), 종료 = `danger` 계열 보조 버튼, 새로고침 = 보조 버튼. 버튼 사이 8px 이상 |
| 하단 | 문서 서비스 설정으로 돌아가기 | 링크 | 연결 있을 때. 누르는 영역 높이 48 |
| 전역 | 성공 Toast | 알림 | 태블릿은 화면 하단 가운데, 최대 폭 480. 페이지 제목을 가리지 않는다(5장 현행 문제) |

### 3.2 태블릿 가로 (960px 이상)

세로 배치를 그대로 쓰고 가운데 정렬한다. 본문 최대 폭 1040px 안에서 마법사 열 폭은 SET-03 3.2와 같다.

### 3.3 휴대폰 (600px 미만)

- 1단, 좌우 여백 16px. 상단 바 56px(제목만), 하단 탭 바 없음(집중 모드).
- 페이지 생성 목록은 1줄 목록 행 56.
- 상태별 주 동작을 하단에 폭 가득 고정한다(하단 안전 영역만큼 띄움): 완료 시 "확인"(`lg` 56), 실패·중단 시 서버가 허용하면 "작업 재개"(`lg` 56). 나머지 버튼(종료, 새로고침)은 카드 안에 폭 가득 `md` 48로 세로로 쌓는다.
- 진행 중에는 고정 버튼을 두지 않는다. "진행 상태 새로고침"은 카드 아래 폭 가득 보조 버튼 `md` 48.
- 작업 종료처럼 되돌릴 수 없는 동작에 확인 단계를 두는 경우 하단 시트로 연다(태블릿은 가운데 대화상자 최대 560px).
- **확인 필요** — Toast 위치. 8장 기준은 "하단 탭 바 위 16"인데 집중 모드에는 탭 바가 없다. 제안: 하단 고정 버튼 위 16, 고정 버튼이 없으면 하단 안전 영역 위 16.

## 4. 상태별 화면

위 "작업 상태" 표와 같으며, 추가로:

| 상태 | 표시 |
|---|---|
| 상세 조회 실패 | 오류 문구 + 진행 상태 다시 불러오기 + 연결 작업 종료 후 다시 연결 |
| 연결 직후 데이터 확인 실패 | "새 연결의 설정 또는 참석자 목록을 불러오지 못했습니다. 연결 데이터를 다시 확인해 주세요." + 연결 데이터 다시 확인 |
| 브라우저 저장 실패 | "연결 정보가 이 브라우저에 저장되지 않았습니다. 브라우저 저장소를 확인해 주세요." |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)**
  - 실패 화면이 작업 ID, 오류 코드(`DOCUMENT_STRUCTURE_CONFLICT` 등), "Provider" 같은 내부 정보를 본문에 그대로 보여 준다(캡처).
  - 버튼 "중단된 연결 작업 종료"와 "진행 상태 새로고침"의 크기·위계가 달라 어색하다(캡처).
  - 성공 Toast가 화면 제목을 가린다(캡처).
- **제안**
  - 실패 시 사용자 행동 중심 안내("Notion에서 'Meeting Automation' 페이지가 이미 있는지 확인해 주세요") + 기술 정보는 "자세히 보기"로 접기, 작업 ID 복사 버튼
  - 오류 코드별 사용자 안내 문구 정의(예: `DOCUMENT_STRUCTURE_CONFLICT` → 같은 이름의 페이지가 이미 있음)
  - 완료 화면에 "연결된 문서 열기" 버튼 추가
- **확인 필요** — 오류 코드 전체 목록과 의미를 Backend 기준으로 정리해야 사용자 문구를 만들 수 있다. 진행 막대 높이, 집중 모드의 Toast 위치(3장). 화면 크기 기준은 D-06(태블릿 기준)으로 결정됨.
