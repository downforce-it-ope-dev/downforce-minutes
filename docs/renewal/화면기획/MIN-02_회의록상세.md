## 1. 화면 개요

문서 서비스에 저장된 회의록을 읽는다. 편집은 하지 않는다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| MIN-02-F01 | 회의 정보 | 제목, 일시, 참석자 이름 | 날짜만 있는 값은 날짜만, 시각이 있으면 날짜+시각 |
| MIN-02-F02 | 회의록 본문 | 요약, 논의 사항, 결정 사항, 실행 항목, 후속 조치 | 내용이 없는 섹션은 숨김. 요약이 없으면 "요약이 없습니다." |
| MIN-02-F03 | 실행 항목 | 할 일 · 담당 · 기한 | 담당자는 참석자 이름으로 표시 |

## 3. 화면 구성 요소

### 3.1 태블릿 (기준, 폭 600px 이상)

화면 기준은 마이크가 있는 태블릿 세로(폭 820px 전후)다. 공통 틀(내비게이션 레일 88px, 상단 바 64px)은 CMN-01을 따르고, 크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4·8장을 따른다. 세로 화면은 1단 읽기 배치이며, 전사 원문은 오른쪽에서 열리는 시트(MIN-02-P01)로 본다.

```
┌──────┬──────────────────────────────────────────────┐
│ [로고]│ ← 회의록 목록          [전사 원문] [원본 문서 ↗] [⋯] │  상단 바 64px
│      ├──────────────────────────────────────────────┤
│  ⌂   │ 주간 회의                                      │  headline
│  홈   │ 2026년 11월 5일 오전 10:00                      │  caption
│  ▤   │ 참석자 홍길동, 김철수, 이영희                      │
│ 회의록 │ [요약] [논의 사항] [결정 사항] [실행 항목] [후속 조치] │  섹션 칩 (가로 스크롤)
│  👥  │ ──────────────────────────────────────────── │
│ 참석자 │ 요약                                           │  title
│  ⚙   │ 이번 회의에서는 ... (본문 body-lg)                 │
│  설정  │ 논의 사항                                       │
│      │ · ...                                         │
│      │ 실행 항목                                       │
│      │ ┌────────────────────────────────────────┐    │
│      │ │ 일정표 공유                               │    │  행 2줄 76px
│      │ │ 담당 홍길동 · 기한 2026.11.12              │    │
│      │ └────────────────────────────────────────┘    │
│  [👤] │ 후속 조치                                       │
└──────┴──────────────────────────────────────────────┘
 레일 88px
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 바 (높이 64px) | 목록으로 | 뒤로 가기 + 링크 | MIN-01. 아이콘 버튼 48×48 + "회의록 목록" |
| | 전사 원문 | 보조 버튼 `md` 48 | MIN-02-P01 열기 (F04). 가로 화면(960px 이상)에서는 오른쪽 패널에 표시하므로 숨긴다 |
| | 원본 문서 열기 | 보조 버튼 `md` 48 | F06 **제안**. 문서 URL이 없으면 숨김 |
| | 더 보기 (⋯) | 아이콘 버튼 48×48 → 메뉴 | 복사·공유(F07 **제안**) 등 부가 동작. 휴대폰은 하단 시트 메뉴 |
| 머리 | 제목 | 제목(h1) | 회의 제목. `headline` (상단 바에는 "회의록 목록" 뒤로 가기만 두고 회의 제목은 본문 머리에 둔다) |
| | 일시·참석자 | 텍스트 | 참석자 없으면 "참석자 정보 없음". `caption`, `text-muted`, 일시는 고정폭 숫자 |
| | 섹션 칩 | 칩 목록 (제안) | 섹션 목차. 내용이 있는 섹션만 표시. 누르면 해당 섹션으로 이동. 칩은 버튼 `sm` 크기(높이 40, 누르는 영역 48), `radius-full`, 현재 섹션은 `selected` 색. 넘치면 가로 스크롤 |
| 배치 (사용자 결정 2026-11-11, 재구성) | 좌우 2단 없이 위아래 한 단. 머리 아래 섹션마다 흰 카드를 쌓고 본문 폭을 그대로 쓴다(읽기 폭 720 제한 없음). 본문 `body-lg`. 실행 항목: 태블릿 이상은 할 일 \| 담당 \| 기한 한 줄(할 일이 길면 줄바꿈), 휴대폰은 2줄(담당·기한이 없으면 "미지정"·"없음") |
| | 논의 사항 / 결정 사항 / 후속 조치 | 섹션 + 목록 | 비어 있으면 숨김. 항목 글자 `body-lg`, 항목 사이 8~12px |
| | 실행 항목 | 섹션 + 목록 행 | 할 일, 담당, 기한. 표 대신 2줄 행(태블릿 76px / 휴대폰 72px): 1줄 할 일(`body`), 2줄 "담당 {이름} · 기한 {날짜}"(`caption`, `text-muted`). 할 일이 길면 행 높이를 늘려 줄바꿈한다(말줄임하지 않음) |
| | 읽기 폭 | 배치 | 본문 최대 폭 720px (스타일 방식 검토 8.6 보조 크기). 태블릿 세로는 레일·여백을 빼면 약 680px이라 화면 폭 그대로 쓰고, 태블릿 가로에서만 제한이 걸린다 |
| 보조 | 전사 원문 보기 | 보조 버튼 | MIN-02-P01. 상단 바 버튼과 같은 동작. 본문 끝에도 보조 버튼 `md` 48로 둘지 **확인 필요** |

- 이 화면은 읽기 전용이라 하단 고정 버튼을 두지 않는다. 읽기 영역을 최대한 확보하기 위해서다.
- 링크·버튼은 hover 없이 항상 보이게 한다. 실행 항목 행은 누르는 동작이 없으므로 누른 상태 색을 쓰지 않는다.

### 3.2 태블릿 가로 (폭 960px 이상)

회의록 본문과 전사 원문을 함께 볼 수 있도록 2단으로 나눈다(현행 문제: 본문과 원문을 같이 볼 수 없음, 5장).

```
┌──────┬──────────────────────────────────────────────────────────────────┐
│ [로고]│ ← 회의록 목록                               [원본 문서 ↗] [⋯]     │  상단 바 64px
│      ├────────────────────────────────────┬─────────────────────────────┤
│  ⌂   │ 주간 회의                            │ [목차] [전사 원문]  ← 탭      │
│  홈   │ 2026년 11월 5일 오전 10:00 · 참석자 …  │                             │
│  ▤   │ ────────────────────────────────── │ 홍길동  00:01                │
│ 회의록 │ 요약                                │ 이번 주 일정은...             │
│  👥  │ ... (body-lg)                      │ 김철수  00:15                │
│ 참석자 │ 논의 사항 · 결정 사항                  │ ...                         │
│  ⚙   │ 실행 항목 (2줄 행)                    │                             │
│  설정  │ 후속 조치                            │                             │
│  [👤] │ (따로 스크롤)                         │ (따로 스크롤)                 │
└──────┴────────────────────────────────────┴─────────────────────────────┘
 레일 88px            왼쪽: 회의록 본문                 오른쪽 패널: 목차 / 전사 원문
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 왼쪽 단 | 머리 + 본문 | 영역 | 3.1과 같다. 섹션 칩은 오른쪽 패널 "목차" 탭으로 옮긴다 |
| 오른쪽 패널 | 탭 | 탭 2개 | 목차 / 전사 원문. 누르는 영역 48 이상, 글자 `label`, 선택 탭 `selected` 색 |
| | 목차 | 목록 | 섹션 이름 1줄 행 60px. 누르면 왼쪽 단의 해당 섹션으로 이동 |
| | 전사 원문 | 목록 | MIN-02-P01과 같은 내용. 발화 `body-lg`, 화자 이름 `label`, 시각 `caption` 고정폭 숫자 |
| | 패널 폭 | 배치 | 384px, MTG-04 오른쪽 패널과 같음 (스타일 방식 검토 8.6 보조 크기) |
| 공통 | 스크롤 | 규칙 | 두 단은 각각 따로 스크롤한다. 좌우 여백 32px |

- 본문 최대 폭 1040px을 넘는 화면은 2단 전체를 가운데 정렬한다.

### 3.3 휴대폰 (폭 600px 미만)

- **배치:** 1단. 상단 바(높이 56px)에 뒤로 가기, 전사 원문 아이콘 버튼, 더 보기(⋯) 아이콘 버튼(각 48×48)을 둔다. 원본 문서 열기(F06 제안)는 ⋯ 메뉴로 옮긴다. 하단 탭 바는 CMN-01을 따른다.
- **머리:** 제목 `headline`(24/32), 일시·참석자 `caption`. 참석자가 많으면 2줄까지 보이고 "외 n명"으로 줄인다(제안).
- **섹션 칩:** 가로 스크롤 칩으로 유지하되 스크롤하면 상단 바 아래에 붙지 않고 함께 올라간다(제안, 읽기 영역 확보).
- **본문:** `body-lg`(17/28), 좌우 여백 16px, 구역 사이 24px.
- **실행 항목:** 2줄 행 72px. 할 일이 길면 줄바꿈해 높이를 늘린다.
- **전사 원문:** MIN-02-P01을 화면 전체를 덮는 시트로 연다.
- **⋯ 메뉴:** 하단 시트(폭 가득, 최대 높이 90%)로 연다. 항목 행 1줄 56px.
- **고정 버튼:** 두지 않는다(읽기 전용 화면).
- **높이가 낮은 화면(`short`, 높이 560px 이하):** 상단 바와 여백을 줄인다.

### 3.4 PC

- 고려하지 않는다(D-06). 넓은 화면에서는 3.2 태블릿 가로 배치를 본문 최대 폭 1040px로 가운데 정렬한다.
- 마우스 hover에서만 나타나는 동작(예: 섹션 제목에 마우스를 올리면 보이는 복사 버튼)은 만들지 않는다.

### 3.5 MIN-02-P01 전사 원문 (시트)

| 요소 | 내용 |
|---|---|
| 제목 | 현행 "Transcript" → "전사 원문"으로 통일 (제안, MTG-04-P01과 동일) |
| 항목 | 화자 이름(참석자 이름 또는 화자 ID), 시작 시각 mm:ss, 발화 |
| 빈 상태 | Transcript가 없습니다. |
| 닫기 | ×(아이콘 버튼 48×48), Esc, 배경 클릭 |
| 크기별 표시 | 태블릿 세로: 오른쪽에서 열리는 시트(폭은 **확인 필요**, MTG-04-P01과 같게). 태블릿 가로: 시트 대신 오른쪽 패널 "전사 원문" 탭(3.2). 휴대폰: 화면 전체 시트 |
| 글자 | 발화 `body-lg`, 화자 이름 `label`, 시작 시각 `caption` 고정폭 숫자(`tabular-nums`) |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)** — 같은 항목의 이름이 검토 화면(MTG-04)과 다르다: 논의 내용↔논의 사항, Transcript↔전사 원문. 회의록 본문과 전사 원문을 같이 볼 수 없다.
- **제안** — 문서형 읽기 레이아웃(본문 `body-lg`, 읽기 폭은 확인 필요), 섹션 목차(태블릿 세로·휴대폰은 섹션 칩, 태블릿 가로는 오른쪽 패널 탭), 실행 항목 2줄 행, 태블릿 가로(960px 이상)에서 전사 원문 오른쪽 패널.
- **확인 필요** — 읽기 폭(기존 제안 720px), 오른쪽 패널·시트 폭, 본문 끝 "전사 원문 보기" 버튼 유지 여부. D-06(지원 화면 크기)은 태블릿 기준으로 결정됨.
- **확인 필요 (기능)** — 저장 후 회의록 수정 기능이 필요한지(현재 Backend는 저장된 회의록 편집 API 없음 — 신규 기능이면 Backend 변경 필요).
