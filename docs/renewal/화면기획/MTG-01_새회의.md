# MTG-01 새 회의

| 항목 | 내용 |
|---|---|
| 화면 ID | MTG-01 |
| 유형 | 페이지 (입력 폼) |
| 경로 | `/meetings/new` |
| 현재 구현 | `frontend/src/NewMeetingPage.tsx`, `MeetingParticipantSelector.tsx`, `App.tsx` `NewMeetingRoute` |
| 진입 조건 | 로그인(신규) + CMN-04 통과 |
| 연결 화면 | 시작 성공 → MTG-02 / 참석자 없음 → PTC-01 / MTG-02에서 돌아오면 입력값 복원 |
| 사용 API | API-001 앱 설정, API-002 템플릿 목록, API-003 참석자 목록, API-006 회의 세션 생성 |
| 현행 캡처 | 없음 |

## 1. 화면 개요

회의 제목, 날짜, 회의록 템플릿, 참석자를 정하고 녹음 세션을 만든다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| MTG-01-F01 | 회의 제목 입력 | 필수 | 앞뒤 공백 제거 후 비어 있으면 오류 |
| MTG-01-F02 | 회의 날짜 선택 | 필수, 기본값 오늘(브라우저 기준) | 날짜 선택기 |
| MTG-01-F03 | 회의록 템플릿 선택 | 필수, 기본 `default.md` | 목록은 API-002. 현재 기본 제공 `default.md`, `project.md` |
| MTG-01-F04 | 참석자 선택 | 1명 이상 필수 | **변경 (2026-11-09):** 펼침 목록이 아니라 화면에 고정된 "참석자 선택 영역"의 목록에서 체크해 고른다(3.1·3.2). 검색, 보기 필터(전체/선택됨), 검색 결과 전체 선택·해제, "n명 선택됨". 검색어를 바꿔도 선택은 유지한다 |
| MTG-01-F05 | 문서 연결 확인 | 문서 연결이 준비됐는지 확인 | API-001의 `setup.status = READY`, `canCreateMeeting`, `connectionVersion ≥ 1`, 회사 시간대 필요 |
| MTG-01-F06 | 회의 시작 | 세션 생성 후 MTG-02 이동 | 제출 중 중복 클릭 방지. 같은 입력의 재시도는 같은 멱등 키 사용 |
| MTG-01-F07 | 연결 변경 감지 | 제출 중 문서 연결이 바뀐 경우 | 설정과 참석자를 다시 불러오고 선택을 초기화한 뒤 안내 |
| MTG-01-F08 | 입력값 복원 | 녹음 화면에서 "회의 준비로 돌아가기" 시 | 제목·날짜·템플릿·참석자 복원 |
| MTG-01-F09 | 참석자 빠른 추가 | 목록에 없는 참석자 추가 | **제안**: 선택 영역 아래 "+ 새 참석자" → PTC-01-P01 팝업 재사용. 추가한 참석자는 바로 선택 상태로 둔다 |
| MTG-01-F10 | CSV 일괄 등록 | 참석자를 여러 명 한 번에 등록 | **요구사항 (2026-11-09).** 선택 영역 아래 "CSV로 일괄 등록" → PTC-01-P03 재사용. 끝나면 목록을 새로 불러오고, 결과 단계에 "방금 등록한 n명 선택" 버튼을 추가로 보인다(이 화면에서 열었을 때만) |

## 3. 화면 구성 요소

크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4절·8장을 따른다. 이 화면은 집중 모드가 아니므로 태블릿은 내비게이션 레일, 휴대폰은 하단 탭 바를 표시한다(CMN-01). 회의 직전에 태블릿을 들고 빠르게 입력하는 장면을 기준으로 한다.

### 3.1 태블릿 (기준, 600px 이상)

태블릿 세로(820×1180) 기준. 위쪽에 회의 정보를 짧게 두고, **남은 높이 전체를 참석자 선택 영역**으로 잡는다(요구사항, 2026-11-09). 회의 시작 버튼은 화면 아래에 고정한다.

```
┌──────┬ 상단 바 64px: ← 새 회의 ──────────────────────────────┐
│ [로고]│  회의 정보                                    title   │
│      │  회의 제목 *                                          │
│  ⌂   │  [                                         ] 52     │
│  홈   │  회의 날짜 *                 회의록 템플릿 *              │
│  ▤   │  [2026-11-05        📅]     [기본 회의록          ▾]   │  ~ 여기까지 약 250
│ 회의록 │ ┌ 참석자 선택 영역 (카드, 남은 높이 전부) ───────────────┐ │
│  👥  │ │ 참석자 *                              3명 선택됨  │ │  머리 48
│ 참석자 │ │ [🔍 이름·이메일 검색                        ] 52 │ │
│  ⚙   │ │ [전체 24] [선택됨 3]          [검색 결과 전체 선택] │ │  48
│  설정  │ ├─────────────────────────────────────────────┤ │
│      │ │ ☑ 홍길동     hong@miinit.com                  │ │  1줄 행 60
│      │ │ ☐ 김철수     kim@miinit.com                   │ │  ← 목록만 따로 스크롤
│      │ │ ☑ 이영희     lee@miinit.com                   │ │     (약 8~9행 보임)
│      │ │ …                                           │ │
│      │ ├─────────────────────────────────────────────┤ │
│      │ │ [+ 새 참석자]   [CSV로 일괄 등록]               │ │  바닥 56
│      │ └─────────────────────────────────────────────┘ │
│      ├─────────────────────────────────────────────────────┤
│  [👤] │  주간 회의 · 기본 회의록 · 3명    [    회의 시작    ] 56 │  하단 고정 80
└──────┴─────────────────────────────────────────────────────┘
 레일 88px
```

**참석자 선택 영역 (태블릿 공통)**

| 항목 | 규칙 |
|---|---|
| 높이 | 화면 높이 − 상단 바 − 회의 정보 − 하단 고정 바 − 여백. 820×1180 세로에서 약 720, 목록 부분 약 520(1줄 행 60 기준 8~9행). 영역 안에서 **목록만 따로 스크롤**하고 머리(제목·검색·필터)와 바닥(새 참석자·일괄 등록)은 영역 안에 고정한다. 회의 시작 버튼은 항상 보인다 |
| 최소 높이 | 목록이 5행(300) 이상 보이게 한다. 화면이 낮아 5행이 안 되면(가로 태블릿에서 키보드가 열린 경우 등) 영역 고정을 풀고 페이지 전체 스크롤로 바꾼다 |
| 카드 | 흰 면 `bg-bg`, `radius-xl`, `shadow-card`(시안 적용 기준 3.3), 안쪽 여백 좌우 20·위 16 |
| 머리 | "참석자 *"(`title`) + 오른쪽 "n명 선택됨"(`label`, 고정폭 숫자, 바뀔 때 스크린리더에 알림). 선택 0명에서 시작을 누르면 이 영역으로 스크롤하고 머리 아래 오류 문구 |
| 검색 | 높이 52, 글자 16. 이름·이메일·팀 부분 일치, 입력 즉시 필터. 지우기 × 48 |
| 팀 거르기 | 선택 상자 "모든 팀 / 팀 이름 / 팀 없음"(높이 52). 검색 오른쪽(태블릿 세로), 검색 아래 줄(태블릿 가로 오른쪽 단은 폭이 좁아 아래 줄). 팀을 고르면 "AX팀 전체 선택" 텍스트 버튼이 보인다(회의에 팀원 전체를 부르는 경우). Backend 팀 확장 전에는 숨긴다(PTC-01 7장) |
| 보기 필터 | 칩 2개 "전체 n" / "선택됨 n"(보이는 높이 40, 누르는 영역 48, 단일 선택, 선택 칩 `selected`). 선택한 사람만 다시 확인할 때 쓴다. 칩 목록(선택됨: 홍길동 × …)은 두지 않는다. 같은 정보를 이 필터로 보여 주고, 칩이 늘어나면 목록 높이를 빼앗기 때문이다 |
| 전체 선택 | 텍스트 버튼 "검색 결과 전체 선택"(팀을 골랐으면 "{팀} 전체 선택") / 모두 선택돼 있으면 "선택 해제". **검색어나 팀 거르기가 있을 때만** 보인다(전체 명단을 한 번에 고르는 실수 방지) |
| 행 | 1줄 행 60: 체크박스(표시 24, `border-input` 테두리, 선택 시 `primary` 면 + 흰 체크) + 이름(`body` 600) + 팀 배지(`accent-soft`, `caption`, 없으면 생략) + 이메일(`caption`, `text-muted`, 넘치면 말줄임). **행 전체가 누르는 영역**(`<label>`). 선택 행은 `selected` 면(시안 적용 기준 S-09: 분홍 계열) + 체크 표시로, 색만으로 구분하지 않는다 |
| 정렬 | 팀 → 이름 가나다순(팀 없음은 맨 뒤). 선택해도 행 위치를 바꾸지 않는다(누르는 순간 행이 움직이면 잘못 누르기 쉽다) |
| 바닥 | "+ 새 참석자"(MTG-01-F09)와 "CSV로 일괄 등록"(MTG-01-F10) 보조 버튼 `md` 48, 사이 8 이상. 목록이 비어 있으면 바닥 대신 빈 상태 안에 같은 버튼을 크게 둔다 |
| 키보드 | 검색에 초점이 가서 화면 키보드가 열리면 영역 머리가 상단 바 아래에 오도록 스크롤해 목록이 키보드 위에 남게 한다 |

| 영역 | 요소 | 유형 | 내용·규칙 | 필수 |
|---|---|---|---|---|
| 상단 바 (높이 64) | 제목, 뒤로 가기 | 제목 | 새 회의. `headline` 28/36, 뒤로 가기 아이콘 버튼 48×48 | - |
| 회의 정보 | 구역 제목 | 제목 | `title` 20/28 | - |
| | 회의 제목 | 텍스트 입력 | 높이 52, 글자 `body` 16, 이름표 `label`, 오류는 아래 `caption` + `danger-soft` 글자색(red-700). 최대 길이 확인 필요(Backend 검증 기준) | 필수 |
| | 회의 날짜 | 날짜 입력 | 높이 52. 기본 오늘. 터치 기기 기본 날짜 선택기 사용 여부 **확인 필요**(현행은 브라우저 날짜 입력) | 필수 |
| | 회의록 템플릿 | 선택 상자 | 높이 52. 템플릿 이름 표시. 태블릿 세로에서는 날짜와 한 줄에 2칸. **제안**: 선택 시 템플릿 구성(섹션) 미리보기 — 가운데 대화상자(최대 폭 560) | 필수 |
| 참석자 | 참석자 선택 영역 | 카드 | 위 "참석자 선택 영역" 표를 따른다. 현행 펼침 목록을 대신한다 | 1명 이상 |
| | 참석자 없음 안내 | 빈 상태 | 영역 안 가운데: "등록된 참석자가 없습니다." + "+ 새 참석자"(주) · "CSV로 일괄 등록"(보조) + 참석자 관리 링크(`link` 글자색, 누르는 영역 48) | - |
| | 검색 결과 없음 | 빈 상태 | "검색 결과가 없습니다." + 검색어 지우기 | - |
| 하단 고정 영역 | 입력 요약 | 텍스트 | **제안**: 제목 · 템플릿 · 참석자 수 1줄 `caption`, `text-muted`. 문서 저장 위치는 공통 상단 바의 문서 연결 상태(CMN-01-F06)로 대신한다 | - |
| | 회의 시작 | 주 버튼 `lg` | 높이 56, `primary`. 로딩·사용 불가 상태에서 비활성. 제출 중 "회의 시작 중…". 하단 안전 영역만큼 띄움 | - |
| | 오류 메시지 | 텍스트 | 버튼 위, `danger-soft` | - |

- **마이크 사전 안내 (제안):** 회의 시작 버튼 위에 "다음 화면에서 마이크 권한을 요청합니다" 안내를 `caption`으로 둔다. 태블릿 마이크로 녹음하는 것이 기본이므로 권한 요청을 미리 알린다.

### 3.3 휴대폰 (600px 미만)

1단. 상단 바 56px, 좌우 여백 16px. 하단 탭 바(64 + 안전 영역)를 표시하고, 회의 시작 버튼을 탭 바 바로 위에 화면 폭 가득 고정한다(CMN-01 3.2).

```
┌ 상단 바 56px: ← 새 회의 ─────────┐
│ 회의 제목 *                      │
│ [                        ] 48  │
│ 회의 날짜 *                      │
│ [2026-11-05          📅]       │
│ 회의록 템플릿 *                   │
│ [기본 회의록              ▾]     │
│ 참석자 *            3명 선택됨    │
│ [🔍 이름·이메일 검색        ]     │
│ [전체 24] [선택됨 3]             │
│ ☑ 홍길동                     72 │
│   hong@…                       │
│ ☐ 김철수                        │
├────────────────────────────────┤
│ [         회의 시작          ] 56│  하단 고정, 폭 가득
├────────────────────────────────┤
│  ⌂ 홈   ▤ 회의록  👥 참석자  ⚙ 설정 │  하단 탭 바 64 + 안전 영역
└────────────────────────────────┘
```

- 입력란 높이 48, 글자 16(Safari 자동 확대 방지). 날짜와 템플릿은 한 줄에 하나씩 쌓는다.
- 참석자 행은 2줄 72. 행 전체를 눌러 선택한다. 휴대폰은 화면이 작아 영역 높이를 고정하지 않고 페이지 전체 스크롤로 본다. 검색·보기 필터·"+ 새 참석자"·"CSV로 일괄 등록"은 태블릿과 같다(일괄 등록은 화면 전체 시트).
- 템플릿 구성 미리보기(제안)와 새 참석자 추가(PTC-01-P01, 제안)는 하단 시트로 띄운다(최대 높이 90%, `radius-xl` 20).
- 요약 카드는 두지 않는다. 필요한 정보는 각 입력란에 이미 보이므로 버튼 위 요약 줄도 생략한다(제안).
- **화면 키보드:** 제목·검색 입력에 초점이 가면 해당 입력란이 키보드에 가리지 않도록 보이는 영역 안으로 스크롤한다. 키보드가 열려 높이가 560px 이하(`short`)가 되면 고정된 회의 시작 버튼을 본문 끝으로 옮겨 입력 영역을 가리지 않게 한다.
- **엄지 범위:** 주 동작(회의 시작)만 하단에 두고, 뒤로 가기는 상단에 둔다. 참석자 목록이 길어도 회의 시작 버튼은 항상 보인다(`short` 제외).

### 3.4 공통 터치 규칙

- hover로만 보이는 요소(참석자 이메일 툴팁, hover 시 나타나는 × 등)는 만들지 않는다. 이메일과 해제 ×는 항상 보인다.
- 누르는 대상은 48×48 이상, 서로 8px 이상 띄운다(8.5).

## 6. 리뉴얼 검토 사항

- **현행 문제 (관찰)** — 참석자가 많아지면 검색 없이 체크박스 목록만 길어진다. 템플릿 선택 라벨이 "회의록 선택"으로 되어 있어 의미가 모호하다. 마이크 사전 점검이 다음 화면에서야 이루어진다.
- **제안** — 태블릿 세로는 1단 폼 + 하단 고정 회의 시작, 태블릿 가로(960px 이상)는 2단 구성(입력 + 요약), 휴대폰은 1단 + 탭 바 위 고정 버튼. 참석자 검색·칩, 행 전체 터치 선택, 템플릿 미리보기, 마이크 권한 사전 안내 문구.
- **결정** — D-06: 마이크가 있는 태블릿 기준, 휴대폰까지 지원, PC는 고려하지 않음(2026-11-06).
- **요구사항 반영 (2026-11-09)** — 태블릿에서 참석자 선택을 고정된 선택 영역(목록 + 체크)으로 잡았다(3.1·3.2). 선택된 참석자 칩 목록은 보기 필터("선택됨 n")로 대신해 없앴다. CSV 일괄 등록(PTC-01-P03)을 이 화면에서도 연다(MTG-01-F10). 참석자의 팀(Backend 확장 예정, PTC-01 7장)으로 거르고 팀 전체를 선택할 수 있다.
- **확인 필요** — 템플릿 미리보기에 필요한 템플릿 본문을 API-002가 주는지 확인(현재 응답 필드 미검증). 참석자 빠른 추가 포함 여부. 터치 기기에서 날짜 입력에 기기 기본 날짜 선택기를 쓸지 여부. 참석자가 매우 많을 때(예: 300명 이상) 목록 성능(가상 스크롤 필요 여부).

## 7. 구현 결정 (2026-11-10, #26 완료)

Preview에서 사용자와 조정해 확정한 구성이다. 3장의 배치·요소와 다르면 이 장이 우선한다. 구현은 `frontend/src/newMeeting/`.

### 7.1 배치 (정보 위계)

| 순서 | 요소 | 규칙 |
|---|---|---|
| 1 | 회의 제목 | 가로 전체. 제목이 길어지므로 글자는 `title` 크기로 키우고, 높이는 다른 입력과 같게(48, 태블릿 52) 맞춘다 |
| 2 | 회의 날짜 · 회의록 템플릿 | 좌우 배치(휴대폰은 위아래). 높이는 제목·참석자 검색과 같다 |
| 3 | 참석자 선택 영역 | 남은 높이를 가로 전체로 쓰고 목록만 스크롤한다(태블릿). 큰 태블릿에서는 검색과 보기 칩을 한 줄에 둔다 |
| 4 | 회의 시작 | 태블릿: 맨 아래 가운데(최대 폭 640). 휴대폰: 탭 바 위 고정 |

- **집중 모드 (2026-11-11):** 메뉴(사이드바·레일·탭 바)를 숨기고 상단 바에는 제목과 뒤로 가기(홈)만 둔다. 새 회의 → 녹음 → 처리 → 검토가 메뉴 없이 이어진다. 큰 태블릿(960px 이상)은 넓어진 폭으로 참석자 목록을 두 단(가나다순을 위에서 아래로)으로 보인다. 휴대폰의 회의 시작은 탭 바가 없으므로 화면 아래에 고정한다.
- "회의 정보" 구역 제목, 입력 요약 줄, 마이크 권한 안내 문구, 템플릿 미리보기는 두지 않는다(S-13).
- 오류·상태 알림은 토스트, 입력 오류는 테두리로만 표시한다.

### 7.2 요소

| 요소 | 결정 |
|---|---|
| 회의 날짜 | 기기 기본 날짜 입력 대신 입력란 모양 버튼("2026년 11월 10일 (화)", 오늘이면 "오늘" 표시) → 큰 달력 대화상자. 날짜 칸 48(태블릿 56), 이전·다음 달, "오늘" 버튼, 방향키 이동 |
| 회의록 템플릿 | 선택 상자 대신 버튼으로 고른다(하나만, 고른 버튼은 분홍 테두리 + 체크) |
| 참석자 행 | 1줄(휴대폰 2줄), 이름 가나다순, 선택해도 순서 고정. 선택 행 배경은 행 사이 4px 간격을 두고 높이를 4px 줄인다 |
| 로그인한 사람 | 로그인 이메일과 같은 참석자를 자동 선택하고 해제할 수 없다("나" 표시). 목록에 없으면 자동 등록하지 않는다 |
| 새 참석자 | 참석자 머리의 등록 아이콘. 태블릿은 참석자 영역 오른쪽에서 왼쪽으로 밀려 나오는 패널(참석자 영역과 같은 높이, 닫으면 다시 가로 전체), 휴대폰은 대화상자. 등록한 사람은 바로 선택된다(API-004). 기존 참석자 관리로 가는 링크는 없앴다 |
| 전체 선택 | 검색어가 있을 때만 "전체 선택 / 선택 해제" |
| 팀·CSV | 팀 배지·거르기(#35), CSV 일괄 등록(#37)은 뒤 묶음에서 붙인다 |

### 7.3 녹음 화면으로 넘기는 값

회의를 만들면 세션과 함께 템플릿 이름·참석자(이름·이메일)를 브라우저 탭 저장소에 넣는다(`frontend/src/meeting/recordingSessionStore.ts`). 녹음 화면의 회의 정보(태블릿 가로)가 이 값을 쓴다(MTG-02 3.2 "확인 필요" 해소).

## 부록: 큰 태블릿 가로 배치 (2026-11-12, 사용자 결정)

큰 태블릿(960 이상)은 왼쪽에 회의 정보(제목 · 템플릿 · 날짜를 위아래, 폭 384), 오른쪽에 참석자를 둔다. 새 참석자 패널이 열리면 참석자 목록과 검색 줄을 한 단으로 바꾼다. 회의 시작은 본문 맨 아래 가운데다. 태블릿 세로·휴대폰은 위아래 배치(제목, 템플릿 · 날짜 한 줄, 참석자) 그대로다.
- 수정(2026-11-12, 사용자 결정): 참석자 목록은 선택한 참석자를 앞쪽에 두고, 선택한 사람끼리·안 한 사람끼리는 이름 가나다순이다(이전: 선택해도 순서 고정). 다른 화면에서 받아 둔 참석자·템플릿 목록이 있으면 새 회의를 열 때 바로 보이고 뒤에서 새로 받는다.
