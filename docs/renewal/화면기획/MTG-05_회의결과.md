## 3. 화면 구성 요소

### 3.1 태블릿 (기준, 폭 600px 이상)

화면 기준은 마이크가 있는 태블릿 세로(폭 820px 전후)다. 공통 틀(내비게이션 레일 88px, 상단 바 64px)은 CMN-01을 따르고, 크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4·8장을 따른다.

```
┌──────┬──────────────────────────────────────────────┐
│ [로고]│ 회의 결과                       [상태 새로고침] │  상단 바 64px
│      ├──────────────────────────────────────────────┤
│  ⌂   │   ✓ 완료                                      │
│  홈   │   주간 회의 · 2026년 11월 5일 (제안)              │
│  ▤   │ ┌ 진행 단계 ─────────────────────────────┐    │
│ 회의록 │ │ ✓ 회의록 저장  회의록 문서가 저장되었습니다.   │    │  행 2줄 76px
│  👥  │ │ ✕ 이메일 전달  1건의 전달에 실패했습니다. [자세히 ▾] │
│ 참석자 │ │                                        │    │
│  ⚙   │ │ ● 완료        일부 전달에 실패했습니다.       │    │
│  설정  │ └────────────────────────────────────────┘    │
│      │ ┌ 이메일 ────────────────────────────────┐    │
│      │ │ 홍길동  hong@…            ✓ 전달 완료    │    │  행 2줄 76px
│      │ │ 김철수  kim@…             ✕ 전달 실패 [재전송] │
│      │ └────────────────────────────────────────┘    │
│      ├──────────────────────────────────────────────┤
│  [👤] │              [저장된 회의록 보기]                │  하단 실행 (고정)
└──────┴──────────────────────────────────────────────┘
 레일 88px
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 바 (높이 64px) | 제목 | 제목(h1) | 회의 결과 (`headline`) |
| | 상태 새로고침 | 보조 버튼 `md` 48 | F10. 항상 표시 (아래 "실행" 행과 같은 버튼을 상단 바에 두는 제안) |
| 요약 | 결과 제목 | 제목 + 상태 아이콘 | F01. `title` + 상태 아이콘. 완료는 `success-soft`, 일부 실패·실패는 `danger-soft`, 진행 중은 `primary-soft`. 색만으로 구분하지 않고 아이콘·문구를 함께 쓴다 |
| | 회의 정보 | 텍스트 | **제안**: 회의 제목·날짜. `caption`, `text-muted`, 날짜는 고정폭 숫자 |
| 진행 단계 | 단계 목록 | 단계 표시기 | 단계명, 상태 라벨, 설명, "다음 조치: …", "오류 코드: …". 단계 하나를 목록 행 2줄(태블릿 76px / 휴대폰 72px)로 표시: 1줄 단계명(`label`) + 상태, 2줄 설명(`caption`). 다음 조치·오류 코드가 있으면 행 높이를 늘려 아래에 붙인다(제안: 오류 코드는 "자세히" 펼침, 5장) |
| | 진행 중 표시 | 상태 | 진행 중 단계는 `primary` 색 진행 표시 + "진행 중" 문구 |
| 이메일 | 수신자 행 | 목록 | 이름, 이메일, 상태, 재전송 버튼(실패 + 재시도 가능). 목록 행 2줄 76px(휴대폰 72px): 1줄 이름(`label`) + 상태, 2줄 이메일(`caption`, `text-muted`, 길면 말줄임). 재전송은 행 오른쪽에 항상 보이는 보조 버튼 `sm` 40(누르는 영역 48) |
| 메시지 | 오류·진행 문구 | 텍스트 | 요청 실패 사유, 진행 안내. 오류는 `danger-soft`, 안내는 `primary-soft` 면 |
| 실행 (하단 고정) | 저장된 회의록 보기 | 주 버튼 `lg` 56 (`primary`) | 모두 완료 시 |
| | 문서 저장 재시도 / 저장 및 전달 재시도 | 주 버튼 `lg` 56 | 허용 시. 하단 고정 영역에는 주 버튼을 하나만 둔다(제안). 두 조건이 동시에 성립할 수 있는지는 **확인 필요** |
| | 상태 새로고침 | 보조 버튼 `md` 48 | 항상 |
| 공통 | 카드 | 영역 | 단계·이메일 구역을 카드로 나눈다. 테두리 `border`, 모서리 `radius-lg` 16, 안쪽 여백 24(휴대폰 16), 구역 사이 32(휴대폰 24) |

- **보이는 양:** 태블릿 세로(820×1180)는 수신자가 10명 안팎이어도 단계·수신자 목록이 대부분 한 화면에 들어온다(추정). 수신자가 많으면 페이지 스크롤로 보며, 실패한 수신자를 목록 위쪽에 먼저 보여 줄지는 **확인 필요**(제안: 실패 우선 정렬).
- **자동 갱신 중 위치 유지:** 1.5초마다 조회(F04)해도 스크롤 위치와 누른 버튼의 초점을 유지한다.

### 3.2 태블릿 가로 (폭 960px 이상)

- 세로 배치를 그대로 쓰고 가운데 정렬한다. 본문 최대 폭은 1040px이다. 2단으로 나누지 않는다.

### 3.3 휴대폰 (폭 600px 미만)

- **배치:** 1단. 상단 바(높이 56px)에 제목과 상태 새로고침 아이콘 버튼(48×48)을 둔다. 하단 탭 바는 CMN-01을 따른다.
- **결과 요약:** 화면 맨 위에 큰 상태 아이콘과 결과 제목을 둔다.
- **목록 행:** 단계·수신자 행은 2줄 72px. 재전송·재시도 버튼은 행 오른쪽에 항상 표시하고, 이메일 주소는 말줄임한다. 실패 원인·오류 코드는 행 아래 "자세히"로 펼친다(제안).
- **하단 실행:** 주 버튼(저장된 회의록 보기 또는 재시도)을 `lg` 56으로 하단 탭 바 위에 화면 폭 가득 고정하고, 하단 안전 영역만큼 띄운다.
- **대화상자:** 이 화면에서 쓰는 확인 창이 생기면 하단 시트로 연다.
- **높이가 낮은 화면(`short`, 높이 560px 이하):** 상단 바와 여백을 줄이고, 고정 주 버튼은 본문 끝으로 옮긴다.

### 3.4 PC

- 고려하지 않는다(D-06). 넓은 화면에서는 태블릿 배치를 본문 최대 폭 1040px로 가운데 정렬한다.
- 재전송·재시도 버튼은 항상 보이게 두고, 마우스 hover에서만 나타나는 동작은 만들지 않는다.

## 4. 상태별 화면

| 상태 | 표시 |

| 일부 실패 | 실패 행에 재전송·재시도 |
| 완료 | 모든 단계 완료 + 저장된 회의록 보기 |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)** — 오류 코드와 기술 문구가 사용자에게 그대로 노출된다. "Retry", "Email" 등 영문·한글 혼용. 완료 후 다음 행동(목록으로, 새 회의)이 약하다.
- **제안**
  - 성공 시 큰 완료 표시 + 저장된 회의록 보기 / 새 회의 시작 / 회의록 목록
  - 오류 코드는 접힌 "자세히" 영역으로 이동
  - 저장된 문서(Notion·Confluence) 원문 바로 열기 링크 — 응답에 문서 URL이 있는지 확인 필요
  - 완료 후 다음 행동 버튼(새 회의 시작, 회의록 목록)은 주 버튼과 구분해 보조 버튼 `md` 48로 둔다. 휴대폰 하단 고정 영역에는 주 버튼 하나만 둔다.
- **결정 (2026-11-06)** — D-07: 발송 대상 선택은 넣지 않는다. D-11: Slack 알림 폐기로 Slack 단계·결과를 표시하지 않는다. Slack 설정을 두지 않으므로 Backend도 Slack 전달 건을 만들지 않는다.
- **확인 필요** — 실패 수신자 우선 정렬 여부. D-06(지원 화면 크기)은 태블릿 기준으로 결정됨

## 6. 구현 결정 (2026-11-11, #30)

Preview 확인 전 구현 구성이다. 3장과 다르면 이 장이 우선한다. 구현은 `frontend/src/complete/`. 로직은 기존 `CompletePage.tsx`에서 `useCompleteSession.ts`로 옮겼다(조회, 확정만 된 회의의 자동 저장·전달 시작, 진행 중 1.5초 자동 갱신, 전달 1건 재전송(같은 클릭 같은 멱등 키, 결과 불명확 시 최신 확인), 저장·전달 재시도).

| 요소 | 결정 |
|---|---|
| 모드 | 집중 모드(메뉴 없음). 뒤로 가기 → 회의록 목록. 상단 바에 상태 새로고침 아이콘 |
| 결과 요약 | 큰 상태 아이콘(완료 초록 체크 / 실패 빨간 × / 진행 중 회전) + 결과 제목(완료 / 전달 중 / 일부 전달 실패 / 회의록 저장 중 / 문서 저장 실패) |
| 단계 | 회의록 저장 → 이메일 전달(전달 건이 있을 때). 행마다 상태 아이콘 + 상태 글자. 실패면 짧은 원인 + "자세히"에 오류 코드를 접어 둔다. **"완료" 단계는 두지 않는다**(사용자 결정 2026-11-11): Slack이 빠져 전달은 이메일뿐이라, 완료 단계가 이메일 전달 단계·위 결과 제목과 같은 내용을 세 번 보였다. 전체 결과는 위 결과 제목·아이콘에서만 보인다 |
| 이메일 | 수신자 행: 이름, 이메일, 상태 알약(전달 완료·전달 중·전달 실패), 실패 + 재시도 가능 + 이메일 설정 완료면 "재전송". 실패한 수신자를 위에 먼저 보인다(5장 확인 필요 → 실패 우선으로 정함) |
| 배치 | 태블릿 가로: 왼쪽 요약·단계, 오른쪽 이메일. 그 밖: 1단 |
| 아래 실행 | 주 동작 하나: 저장된 회의록 보기(모두 완료) 또는 저장 재시도 / 다시 전달. 다음 행동: 새 회의, 회의록 목록(보조) |
| 알림 | 안내·오류는 토스트(S-13) |
| Slack (D-11) | Slack 단계·결과를 보이지 않는다. 저장·전달 요청(검토 화면 발송 포함)에 알림을 켜지 않는다(`notificationEnabled: false`). 앱 시작 시 Slack 설정 복구를 없앴다. 설정 화면의 Slack 카드와 저장소 코드는 #39에서 지운다 |

- 기존 `CompletePage`·테스트·`share.css`를 지웠다. 기존 화면 계산 스타일 차이 없음.
