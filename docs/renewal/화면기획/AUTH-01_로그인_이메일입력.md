# AUTH-01 로그인 — 이메일 입력 (신규)

| 항목 | 내용 |
|---|---|
| 화면 ID | AUTH-01 |
| 유형 | 페이지 (인증 전용 레이아웃) |
| 경로 | `/login` (제안) |
| 현재 구현 | 없음 — 신규 |
| 진입 조건 | 로그인하지 않은 상태로 서비스 진입, 로그아웃, 세션 만료, AUTH-02에서 "이메일 변경" |
| 연결 화면 | 발송 성공 → AUTH-02 |
| 사용 API | **신규 필요**: 인증 코드 발송 요청 (예: `POST /auth/otp/request`) — D-01 |
| 현행 캡처 | 없음 |

## 1. 화면 개요

회사 이메일 주소를 입력하면 해당 주소로 6자리 인증 코드(OTP, One-Time Password)를 보낸다. 서비스의 첫 화면이다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| AUTH-01-F01 | 이메일 입력 | 회사 이메일 주소 입력 | 앞뒤 공백 제거, 소문자로 정규화 |
| AUTH-01-F02 | 형식 검증 | 이메일 형식 확인 | 형식이 틀리면 버튼 클릭 시 입력란 아래 오류 표시 |
| AUTH-01-F03 | 회사 도메인 검증 | 허용 도메인 여부 확인 | 허용 도메인 목록은 미정(D-02). 화면과 서버 모두 검증 |
| AUTH-01-F04 | 인증 코드 요청 | 서버에 코드 발송 요청 | 요청 중 버튼 비활성·로딩 표시. 성공 시 AUTH-02로 이동하며 이메일 전달 |
| AUTH-01-F05 | 요청 제한 안내 | 짧은 시간 반복 요청 차단 | 서버가 거절(429)하면 남은 대기 시간 안내 |
| AUTH-01-F06 | 원래 경로 기억 | 로그인 후 원래 가려던 화면으로 이동 | 진입 시 요청한 경로를 보관해 AUTH-02 성공 후 사용 (내부 경로만 허용) |

## 3. 화면 구성 요소

화면 기준은 마이크가 있는 태블릿이다. PC 전용 배치는 만들지 않는다(D-06). 크기·글자·컴포넌트 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 8장을 따른다. 인증 화면은 공통 레이아웃(CMN-01)의 내비게이션 레일·하단 탭 바·상단 바를 쓰지 않는다.

### 3.1 태블릿 (기준, 폭 600px 이상)

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│        ┌──────────────────────────────────┐          │
│        │     [Downforce Minutes 로고]       │          │
│        │                                  │          │
│        │  회사 이메일로 로그인                │ headline │
│        │  회사 이메일로 받은 6자리 코드로       │          │
│        │  로그인합니다.                      │ body     │
│        │                                  │          │
│        │  이메일                            │ label    │
│        │  ┌────────────────────────────┐  │          │
│        │  │ name@company.com           │  │ 높이 52   │
│        │  └────────────────────────────┘  │          │
│        │  (오류 메시지 영역)                 │ caption  │
│        │                                  │          │
│        │  [        인증 코드 받기        ]  │ lg 56    │
│        │                                  │          │
│        │  로그인에 문제가 있으면              │          │
│        │  관리자에게 문의하세요.              │ caption  │
│        └──────────────────────────────────┘          │
│                    화면 가운데 정렬                     │
└──────────────────────────────────────────────────────┘
 태블릿 세로 약 820px, 메뉴 없음
```

| 영역 | 요소 | 유형 | 내용·규칙 | 필수 |
|---|---|---|---|---|
| 배경 | 인증 레이아웃 | 레이아웃 | 메뉴 없음(레일·탭 바·상단 바 없음). 배경 `bg`(흰색). 가운데 카드: 테두리 `border`, 모서리 `radius-lg`(16), 안쪽 여백 24, 그림자 없음. 카드 최대 폭은 **확인 필요** (제안: 480px. 8장에 인증 카드 폭 기준이 없음) | - |
| 머리 | 로고 | 이미지 | Downforce Minutes (다운포스 CI, D-10). 로고 크기는 **확인 필요** (CI 로고 규정 7.2 확인 후 결정) | - |
| | 제목 | 제목(h1) | 회사 이메일로 로그인. `headline`(태블릿 28/36) | - |
| | 설명 | 텍스트 | 회사 이메일로 받은 6자리 코드로 로그인합니다. `body`, `text-muted` | - |
| 입력 | 이메일 | 텍스트 입력 | `type=email`, `inputmode=email`(이메일 키보드), `autocomplete=email`, `autocapitalize=off`, 자동 초점, Enter(키보드의 이동·완료 키)로 제출. 높이 52(태블릿), 글자 16px(`body`), 테두리 `border-input`, 초점 시 `focus` 색, 모서리 `radius-md`(12). 이름표 "이메일"은 위에 `label` | 필수 |
| | 오류 메시지 | 텍스트 | 입력란 바로 아래 `caption`, `danger-soft` 글자색(red-700) + 오류 아이콘(색만으로 구분하지 않음). `aria-describedby`로 연결 | - |
| 실행 | 인증 코드 받기 | 주 버튼 | 버튼 `lg`(높이 56, `label` 16), `primary` 색, 카드 폭 가득. 입력이 비어 있으면 비활성. 요청 중 "보내는 중…" | - |
| 하단 | 도움말 | 텍스트 | 문의 안내 `caption`, `text-muted` (문구·연락처 확인 필요) | - |
| 상단 안내 | 경고·오류·안내 배너 | 배너 | 카드 위쪽(제목 위)에 표시. 요청 과다 `warning-soft`, 발송 실패 `danger-soft`, 세션 만료 `primary-soft` + 아이콘 | - |

- 화면 키보드가 열려 높이가 560px 이하(`short`)가 되면 로고를 줄이거나 숨기고 위아래 여백을 줄여 입력란과 버튼이 키보드 위에 보이게 한다.

### 3.2 태블릿 가로 (폭 960px 이상)

세로 배치를 그대로 쓰고 카드를 화면 가운데에 둔다. 넓은 화면(PC 포함)도 같다.

### 3.3 휴대폰 (폭 600px 미만)

- 카드 테두리 없이 화면 전체를 1단으로 쓴다. 좌우 여백 16px, 위쪽 안전 영역(`env(safe-area-inset-top)`)만큼 띄운다.
- 제목은 `headline` 휴대폰 크기(24/32), 입력란 높이 48px(글자 16px 유지).
- 주 버튼(인증 코드 받기)은 입력란 아래에 화면 폭 가득 배치한다. 하단 탭 바가 없는 화면이므로 하단 고정하지 않는다(키보드가 열렸을 때 버튼이 가려지거나 들뜨지 않도록).
- `short`(높이 560px 이하, 키보드 열림·휴대폰 가로)에서는 로고를 숨기고 설명 문구를 줄여 입력란과 버튼이 키보드 위에 보이게 한다.

## 4. 상태별 화면

| 상태 | 조건 | 표시 |
|---|---|---|
| 기본 | 진입 | 빈 입력란, 버튼 비활성 |
| 입력 중 | 값 있음 | 버튼 활성 |
| 요청 중 | 버튼 클릭 | 입력·버튼 비활성, 버튼에 로딩 표시 |
| 형식 오류 | 이메일 형식 아님 | 입력란 빨간 테두리(`danger`) + 오류 아이콘 + 오류 문구 |
| 도메인 오류 | 허용 도메인 아님 | 입력란 오류 + 문구 |
| 요청 과다 | 서버 429 | 상단 경고 + 남은 시간 |
| 발송 실패 | 서버·메일 오류 | 상단 오류 배너 + 다시 시도 |
| 세션 만료로 진입 | 만료 후 이동 | 상단 안내 배너 "로그인이 만료되었습니다. 다시 로그인해 주세요." |

## 5. 메시지 (초안)

| 구분 | 문구 |
|---|---|
| 빈 값 | 이메일을 입력해 주세요. |
| 형식 오류 | 올바른 이메일 주소를 입력해 주세요. |
| 도메인 오류 | 회사 이메일 주소로만 로그인할 수 있습니다. |
| 요청 과다 | 잠시 후 다시 시도해 주세요. ({n}초 후 가능) |
| 발송 실패 | 인증 코드를 보내지 못했습니다. 잠시 후 다시 시도해 주세요. |

## 6. 리뉴얼 검토 사항

- **보안 (제안)** — 등록되지 않은 사용자가 입력해도 같은 화면 흐름(AUTH-02)으로 보내 계정 존재 여부를 노출하지 않는 방식을 권장한다. 다만 허용 대상 정책(D-02)에 따라 UX가 달라진다.
- **확인 필요**
  - D-01: 인증 API 신규 개발과 기존 API 인증 적용 범위 (Backend 변경 제약과 충돌)
  - D-02: 허용 대상 — 회사 도메인 전체 / 참석자 목록 등록자 / 별도 사용자 목록
  - D-03: 코드 발송 메일 계정 — SET-01의 Gmail 연동을 쓰면 연동 전에는 로그인이 불가능하다
  - 도메인 고정 표시 여부 — 입력란 뒤에 `@회사도메인`을 고정 표시하고 아이디만 받는 방식도 가능
  - 인증 카드 최대 폭(제안 480px)과 로고 크기 — 8장에 기준 없음
