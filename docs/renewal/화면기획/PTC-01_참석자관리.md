# PTC-01 참석자 관리

| 항목 | 내용 |
|---|---|
| 화면 ID | PTC-01 |
| 유형 | 페이지 (목록 + 팝업 편집) |
| 경로 | `/participants` (`/settings/participants`도 같은 화면) |
| 현재 구현 | `frontend/src/App.tsx` `ParticipantsPage`, `participantsApi.ts` |
| 진입 조건 | 로그인(신규) + CMN-04 통과 |
| 연결 화면 | MTG-01·MTG-04의 "참석자 관리" 링크로 진입 |
| 하위 팝업 | PTC-01-P01 참석자 추가·수정, PTC-01-P02 참석자 삭제 확인, PTC-01-P03 CSV 일괄 등록 |
| 사용 API | API-003 목록, API-004 추가(일괄 등록은 1건씩 반복 호출), API-005 수정, API-031 삭제 |
| 현행 캡처 | [참석자 화면](<../현_UI/참석자 화면.png>), [참석자 추가 화면](<../현_UI/참석자 추가 화면.png>) |

## 1. 화면 개요

회의에 선택할 참석자(이름, 이메일)를 관리한다. 참석자 정보는 연결된 문서 서비스(Participants 페이지)에 저장되며, 회의록 이메일 수신자로 쓰인다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| PTC-01-F01 | 참석자 목록 | 이름, 이메일 | 이름 첫 글자 아바타 |
| PTC-01-F02 | 검색 | 이름 또는 이메일 | 입력 즉시 화면 내 필터, 지우기 버튼 |
| PTC-01-F03 | 참석자 추가 | PTC-01-P01 | 이름·이메일 필수, 이메일 형식 검사 + **`@miinit.com` 도메인만 허용**(결정 2026-11-09, CSV 일괄 등록과 같은 규칙). 같은 입력 재시도는 같은 멱등 키 |
| PTC-01-F04 | 참석자 수정 | PTC-01-P01 | 바뀐 값만 전송. 변경 없으면 그냥 닫음. 이메일을 바꿀 때만 도메인을 검사한다(기존 회사 외 주소 참석자는 이메일을 그대로 두면 이름·팀 수정 가능) |
| PTC-01-F05 | 참석자 삭제 | PTC-01-P02 확인 후 | 문서 서비스에서 삭제 |
| PTC-01-F06 | 결과 알림 | Toast | 참석자를 추가했습니다 / 수정했습니다 / 삭제했습니다 |
| PTC-01-F07 | 충돌 처리 | 문서 변경 중·버전 충돌·이미 삭제됨 | 서버 문구 표시, 필요 시 "목록 새로고침" |
| PTC-01-F08 | CSV 일괄 등록 | 엑셀에서 저장한 CSV 파일로 여러 명을 한 번에 등록 | **요구사항 (2026-11-09).** PTC-01-P03. **CSV만 받는다**(`.xlsx`는 받지 않음, 외부 라이브러리 없음). 열은 팀·메일계정·이름 3개. 메일계정은 `@miinit.com`만 허용. 파일은 브라우저에서 읽고, 등록은 API-004를 1건씩 순서대로 호출한다(Backend 일괄 API 없음). 이미 등록된 이메일은 건너뛴다. 상세는 3.6 |
| PTC-01-F09 | 양식 내려받기 | 일괄 등록용 CSV 양식 | 정적 파일 `participants-template.csv`(UTF-8 BOM). 머리글 `팀,메일계정,이름` + 예시 1행. PTC-01-P03 첫 단계에서 내려받는다 |
| PTC-01-F10 | 팀 | 참석자의 소속 팀 | **신규 (2026-11-09, Backend 확장 전제).** 목록에 팀 표시, 팀으로 검색·거르기, 추가·수정 폼에 팀 입력. Backend 계약은 7장 |

## 3. 화면 구성 요소

크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4·8장을 따른다. 공통 틀(내비게이션 레일, 상단 바, 하단 탭 바)은 CMN-01을 따른다.

### 3.1 태블릿 (기준, 600px 이상)

```
┌──────┬──────────────────────────────────────────────────────┐
│ [로고]│ 참석자                  [CSV로 일괄 등록] [+ 참석자 추가] │  상단 바 64px
│      ├──────────────────────────────────────────────────────┤
│  ⌂   │ [🔍 이름·이메일·팀 검색             ✕ ] [모든 팀   ▾]   │  검색 52px
│  홈   │                                          참석자 12명   │
│  ▤   │ ┌──────────────────────────────────────────────────┐ │
│ 회의록 │ │ (홍) 홍길동 [AX팀]                   [수정] [삭제] │ │  2줄 행 76px
│  👥  │ │      hong@miinit.com                             │ │
│ 참석자 │ ├──────────────────────────────────────────────────┤ │
│  ⚙   │ │ (김) 김철수                          [수정] [삭제] │ │
│  설정  │ │      kim@company.com                             │ │
│      │ └──────────────────────────────────────────────────┘ │
│  [👤] │                                                      │
└──────┴──────────────────────────────────────────────────────┘
 레일 88px
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 바 (64px) | 제목 | 제목(h1) | 참석자. `headline` |
| | 참석자 추가 | 주 버튼 `md` 48 | 현행: 화면 하단 고정 → 태블릿은 상단 바 우측(제안). 색 `primary` |
| | CSV로 일괄 등록 | 보조 버튼 `md` 48 | PTC-01-F08. 참석자 추가 버튼 왼쪽, 사이 8px 이상. 표 아이콘 + 문구 "CSV로 일괄 등록". 누르면 PTC-01-P03 |
| 검색 | 검색 입력 | 검색 상자 | 높이 52, 글자 16px. placeholder "이름·이메일·팀 검색". 지우기는 입력란 안 아이콘 버튼(누르는 영역 48) |
| | 팀 거르기 | 선택 상자 | PTC-01-F10. 검색 옆, 높이 52. "모든 팀" / 팀 이름(가나다순) / "팀 없음". 팀 목록은 참석자 목록에서 모은다 |
| | 인원 수 | 텍스트 | 참석자 목록 n명. `caption`, `text-muted` |
| 목록 | 참석자 행 | 2줄 목록 행 76 | 아바타(이름 첫 글자) + 1줄: 이름(`body`, 600) + 팀 배지(`accent-soft`, `caption`, 팀이 없으면 생략) / 2줄: 이메일(`caption`, `text-muted`). 행 구분선 `border`. 정렬: 팀 → 이름 가나다순 |
| | 수정 / 삭제 | 버튼 `sm` 40 (누르는 영역 48) | 행 오른쪽에 항상 보이게 둔다. hover로 나타나는 버튼은 쓰지 않는다. 삭제는 글자 색 `danger` 계열 보조 버튼, 두 버튼 사이 8px 이상 |
| | 행 누르기 | 동작 | **제안**: 행 전체를 누르면 수정(P01)을 연다. 수정 버튼과 같은 동작 |
| 본문 | 여백 | - | 좌우 24px, 구역 사이 32px |

### 3.2 태블릿 가로 (960px 이상)

목록 + 편집 패널 2단을 쓴다(제안).

```
┌──────┬──────────────────────────────────────────────────────────────────┐
│ [로고]│ 참석자                                              [+ 참석자 추가] │
│      ├────────────────────────────────┬─────────────────────────────────┤
│  ⌂   │ [🔍 이름 또는 이메일 검색    ✕ ] │ 참석자 수정                        │
│  ▤   │                    참석자 12명  │                                 │
│  👥  │ ┌────────────────────────────┐ │ 이름                              │
│  ⚙   │ │ (홍) 홍길동          [⋯] │◀│ [홍길동                       ]   │
│      │ │      hong@company.com      │ │ 이메일                            │
│      │ ├────────────────────────────┤ │ [hong@company.com             ]   │
│      │ │ (김) 김철수          [⋯] │ │                                 │
│      │ │      kim@company.com       │ │ [삭제]                    [저장]  │
│      │ └────────────────────────────┘ │                                 │
└──────┴────────────────────────────────┴─────────────────────────────────┘
```

| 영역 | 요소 | 내용·규칙 |
|---|---|---|
| 왼쪽 목록 | 참석자 행 | 2줄 목록 행 76. 선택된 행은 `selected` 배경(보라 계열) + 글자 굵기로도 표시. 행 끝 ⋯ 메뉴(아이콘 버튼 48): 수정, 삭제 |
| 오른쪽 패널 | 편집 패널 | 선택한 참석자의 P01 입력 내용을 대화상자 대신 패널로 표시. "참석자 추가"도 같은 패널에 빈 폼으로 연다. 선택 전에는 "참석자를 선택하거나 새로 추가해 주세요."(제안) 안내 |
| | 저장 / 삭제 | 저장은 주 버튼 `md` 48(`primary`), 삭제는 `danger` 보조 버튼. 삭제는 P02 확인을 거친다 |
| 공통 | 목록 표 | 표 형식은 쓰지 않는다. 쓰더라도 이 폭에서만, 행 높이 48 이상을 지킬 때만 허용한다 |

- **확인 필요** — 패널에서 저장하지 않은 수정이 있는 채로 다른 행을 누를 때의 처리. 제안: CMN-01-P01과 같은 이탈 확인을 재사용한다.

### 3.3 휴대폰 (600px 미만)

```
┌──────────────────────────────┐
│ 참석자                [문서●] │  상단 바 56px
├──────────────────────────────┤
│ [🔍 이름 또는 이메일 검색  ✕ ] │  검색 48px
│                  참석자 12명  │
│ (홍) 홍길동              [⋯] │  2줄 행 72px
│      hong@company.com        │
│ (김) 김철수              [⋯] │
│      kim@company.com         │
│                              │
├──────────────────────────────┤
│ [       + 참석자 추가       ] │  주 버튼 lg 56, 폭 가득
├──────────────────────────────┤
│  홈   회의록   참석자   설정   │  하단 탭 바 64 + 안전 영역
└──────────────────────────────┘
```

- 1단 배치, 좌우 여백 16px.
- 참석자 행은 2줄 목록 행 72. 수정·삭제는 행 끝 ⋯ 메뉴(아이콘 버튼 48)로 모은다. 행을 누르면 수정(P01)을 연다(제안).
- 팀 거르기는 검색 아래 줄에 폭 가득 둔다.
- "CSV로 일괄 등록"은 상단 바 오른쪽 ⋯ 메뉴(아이콘 버튼 48)에 둔다. 상단 바 폭이 좁아 버튼 두 개를 나란히 둘 수 없다. 빈 상태 화면에서는 보조 버튼으로 바로 보인다(4장).
- "참석자 추가"는 주 버튼 `lg` 56, 화면 폭 가득으로 하단 탭 바 위에 고정한다(CMN-01 3.2).
- `short`(높이 560px 이하, 키보드 열림)에서는 고정 버튼을 목록 끝으로 옮긴다.

### 3.4 PTC-01-P01 참석자 추가·수정

| 요소 | 유형 | 내용·규칙 |
|---|---|---|
| 보조 제목 / 제목 | 텍스트 | 참석자 관리 / 참석자 추가 또는 참석자 수정. 제목 `title` |
| 설명 | 텍스트 | 이름과 이메일 정보를 입력해 주세요. `body`, `text-muted` |
| 이름 | 텍스트 입력 | 필수, 열릴 때 자동 초점, `autocomplete=name`. 입력란 48/52, 글자 16px, 이름표 `label` 위 |
| 팀 | 텍스트 입력 + 제안 목록 | **신규 (PTC-01-F10).** 선택 입력, 최대 50자(제안). 입력하면 기존 팀 이름을 아래 목록으로 제안해 같은 팀을 다른 표기로 만들지 않게 한다(목록 행 48). 이름 아래에 둔다 |
| 이메일 | 이메일 입력 | 필수, 형식 검사 + **`@miinit.com` 도메인만 허용**(대소문자 무시, 결정 2026-11-09). 입력란 아래 도움말 "회사 메일(@miinit.com)만 등록할 수 있습니다."(`caption`, `text-muted`, `aria-describedby`로 연결). 검사는 입력란을 벗어날 때와 저장할 때 한다. 수정 폼에서는 이메일을 바꿨을 때만 도메인을 검사한다. 입력란 48/52, 글자 16px. 화면 키보드가 이메일 배열로 열리도록 `type=email`, `autocomplete=email`, 자동 대문자·자동 수정 끔(제안) |
| 오류 | 텍스트 | 입력란별 오류(입력란 아래 `caption`, `danger-soft` 글자 색) + 폼 오류(`danger-soft` 안내 상자, 아이콘 함께) |
| 목록 새로고침 | 보조 버튼 | 대상이 사라진 경우. 버튼 `md` 48 |
| 저장 | 주 버튼 | 저장 중 "저장 중…". 버튼 `md` 48(태블릿), 휴대폰은 시트 하단 폭 가득 `lg` 56 |
| 닫기 | 아이콘 버튼 48 | ×, Esc(외부 키보드). 저장 중에는 닫기 불가. 닫으면 연 버튼으로 초점 복귀 |
| 형태 (제안) | 대화상자 | 휴대폰은 하단 시트(폭 가득, 최대 높이 90%), 태블릿 세로는 가운데 대화상자(최대 폭 560px), 태블릿 가로는 3.2 편집 패널. 안쪽 여백 24, 모서리 `radius-xl`, `shadow-overlay`. 현행은 넓은 화면에서도 전체 화면 |
| 키보드 열림 (`short`) | 규칙 | 시트가 키보드 위로 올라오고, 저장 버튼은 시트 하단 고정을 풀고 입력란 아래(본문 끝)로 옮긴다. 초점이 간 입력란이 키보드에 가리지 않게 스크롤한다 |

### 3.5 PTC-01-P02 참석자 삭제 확인

| 요소 | 내용 |
|---|---|
| 제목 | 삭제하시겠습니까? |
| 본문 | **{이름}** 참석자 정보를 연결된 문서 서비스에서 삭제합니다. |
| 버튼 | 아니요 / 예(위험) — 제안: "취소 / 삭제"로 명확화. 버튼 `md` 48, 삭제는 `danger` 배경. 휴대폰은 두 버튼을 세로로 폭 가득 쌓는다(제안) |
| 형태 | 휴대폰 하단 시트 / 태블릿 가운데 대화상자 최대 560px |
| 오류 | 이미 삭제된 참석자입니다. 목록을 새로고침해 주세요. 등. `danger-soft` 안내 |

### 3.6 PTC-01-P03 CSV 일괄 등록 (요구사항, 2026-11-09)

엑셀에서 CSV로 저장한 파일에 적힌 참석자(팀·메일계정·이름)를 확인한 뒤 한 번에 등록한다. 한 대화상자 안에서 4단계(파일 선택 → 확인 → 등록 → 결과)로 진행한다.

**형태**

| 화면 | 형태 |
|---|---|
| 태블릿 (600px 이상) | 가운데 대화상자. 최대 폭 640(`max-w-form`, 미리보기 목록 때문에 일반 대화상자 560보다 넓게), 최대 높이 화면의 90%. 안쪽 여백 24, `radius-xl`, `shadow-overlay`. 머리(제목·단계 표시·닫기)와 아래 버튼 줄은 고정하고 가운데만 스크롤한다 |
| 휴대폰 (600px 미만) | 화면 전체 시트. 아래 버튼 줄은 하단 안전 영역만큼 띄워 고정한다 |
| 공통 | 머리에 단계 표시 "1 파일 선택 · 2 확인 · 3 등록"(현재 단계 `aria-current="step"`, 색 + 번호·굵기로 구분). 닫기 × 48×48 |

```
┌ CSV로 일괄 등록 ──────────── 1 파일 선택 · 2 확인 · 3 등록 ─ [×] ┐
│                                                               │
│  2단계: 확인                                                   │
│  [등록 예정 18] [팀 갱신 2] [이미 등록됨 3] [오류 2]   ← 보기 필터 칩 │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ 행  팀      이름     메일계정              상태             │ │ 머리 줄
│  │ 2   AX팀    홍길동   hong@miinit.com      [등록 예정]       │ │ 1줄 행 60
```

**1단계: 파일 선택**

| 요소 | 내용·규칙 |
|---|---|
| 안내 | "엑셀에서 '다른 이름으로 저장 → CSV'로 저장한 파일을 올려 주세요. 팀·메일계정·이름을 읽어 참석자로 등록합니다." `body`, `text-muted` |
| 양식 내려받기 | 보조 버튼 `md` 48. PTC-01-F09 양식 `participants-template.csv` |
| 파일 선택 영역 | 높이 160, 점선 테두리 `border-input`, `radius-lg`. 영역 전체가 누르는 대상(`<label>`로 숨은 파일 입력과 연결, `accept=".csv,text/csv"`)이고 가운데에 "파일 선택" 버튼 모양. 태블릿에서는 기기 파일 선택기(파일 앱·드라이브)가 열린다. 끌어다 놓기는 보조 수단으로만 지원한다 |
| 허용 파일 | `.csv`만. 최대 1MB, 데이터 최대 200행(**제안**, 확인 필요). `.xlsx`를 고르면 "엑셀 파일은 CSV로 저장한 뒤 올려 주세요." 안내 |
| 개인정보 | 파일은 브라우저 안에서만 읽고 서버로 보내지 않는다. 등록할 각 참석자의 팀·이름·이메일만 API-004로 보낸다. 대화상자를 닫으면 읽은 내용을 지운다 |

**CSV 파일 구조**

| 항목 | 규칙 |
|---|---|
| 열 (3개, 모두 필수 머리글) | `팀`, `메일계정`, `이름`. 첫 행이 머리글이다. **열 순서는 상관없다**(머리글 이름으로 찾음). 다른 열은 무시한다 |
| 머리글 별칭 | 팀: `팀`·`소속`·`team` / 메일계정: `메일계정`·`메일`·`이메일`·`email` / 이름: `이름`·`성명`·`name`. 대소문자·앞뒤 공백·BOM은 무시한다. 셋 중 하나라도 없으면 1단계에서 오류 |
| 인코딩 | 앞에 UTF-8 BOM이 있으면 UTF-8. 없으면 UTF-8로 엄격하게 읽어 보고, 깨지면 CP949(한국어 Excel의 기본 CSV 저장 형식, 브라우저 `TextDecoder('euc-kr')`)로 다시 읽는다. 둘 다 실패하면 오류 |
| 구분자·따옴표 | 쉼표(`,`)만. 큰따옴표로 감싼 값 안의 쉼표·줄바꿈 허용, `""`는 큰따옴표 하나(RFC 4180). 줄 끝 CRLF·LF 모두 허용 |
| 값 정리 | 앞뒤 공백 제거. 빈 행(세 값 모두 빈 행)은 건너뛴다. 메일계정은 소문자로 바꿔 비교·저장한다(제안) |
| 메일계정 | 이메일 형식 + **`@miinit.com` 도메인만 허용**(대소문자 무시, 결정 2026-11-09). 다른 도메인은 오류 행 |
| 팀 | 비어 있어도 된다(오류 아님, "팀 없음"으로 등록). 최대 50자(제안). 같은 팀 이름의 앞뒤 공백·대소문자 차이는 하나로 맞춘다(제안: 기존 팀 이름 표기를 따름) |
| 이름 | 필수. 최대 길이는 Backend 기준을 따른다(확인 필요) |
| 양식 예시 | `팀,메일계정,이름` / `AX팀,hong@miinit.com,홍길동` (UTF-8 BOM, Excel에서 열어도 한글이 깨지지 않게) |
**2단계: 확인 (미리보기)**

| 요소 | 내용·규칙 |
|---|---|
| 기준 목록 | 이 단계에 들어갈 때 API-003으로 참석자 목록을 다시 불러와 중복을 판단한다(다른 사람이 그사이 등록했을 수 있음) |
| 요약 칩 | 등록 예정 n · 팀 갱신 n · 이미 등록됨 n · 오류 n. 칩을 누르면 그 상태만 보인다(보기 필터, 다시 누르면 전체). 칩 보이는 높이 40, 누르는 영역 48 |
| 행 목록 | 태블릿: 머리 줄(행·팀·이름·메일계정·상태) + 1줄 행 60. 행 번호는 CSV의 실제 줄 번호(`caption` 고정폭 숫자). 휴대폰: 2줄 행 72(1줄 이름 + 팀 배지 + 상태 배지, 2줄 메일계정·행 번호) |
| 상태 판정 | **등록 예정**: 이름 있음 + 메일계정 형식·도메인 맞음 + 기존 목록·파일 안에 같은 메일계정 없음. **팀 갱신**: 기존 참석자와 메일계정이 같고 팀만 다름(기존 팀이 비어 있는 경우 포함) → 팀만 API-005로 바꾼다(제안, 아래 선택). **이미 등록됨**: 메일계정·팀이 같음 → 건너뛴다. 기존 이름이 파일과 달라도 이름은 바꾸지 않는다. **파일 안 중복**: 같은 메일계정이 앞 행에 있음 → 첫 행만 처리. **오류**: 이름 없음, 메일계정 없음, 형식 틀림, `@miinit.com` 아님 |
| 팀 갱신 선택 | "기존 참석자의 팀 정보도 갱신" 체크박스(행 48, 기본 켬, 제안). 끄면 팀 갱신 행은 "이미 등록됨"으로 처리한다. Backend 팀 확장 직후 기존 참석자에게 팀을 한 번에 채우는 데 쓴다 |
| 상태 배지 | 등록 예정 `accent-soft`, 팀 갱신 `primary-soft`, 이미 등록됨·파일 안 중복 `bg-subtle` + `text-muted`, 오류 `danger-soft` + 경고 아이콘 + 사유 문구. 색만으로 구분하지 않는다 |
| 오류 처리 | 오류 행은 등록하지 않고 제외한다. 이 화면에서 직접 고치지 않는다(파일을 고쳐 다시 올림). 안내: "오류 n행은 등록하지 않습니다. 파일을 고친 뒤 다시 올릴 수 있습니다." |
| 버튼 | 왼쪽 "다른 파일 선택"(보조 `md` 48, 1단계로), 오른쪽 "n명 등록·m명 팀 갱신"(주 `lg` 56). 처리할 행이 0이면 주 버튼 비활성 + "새로 등록하거나 갱신할 참석자가 없습니다." |

**3단계: 등록 진행**

| 요소 | 내용·규칙 |
|---|---|
| 호출 방식 | 등록 예정은 API-004(`{name,email,team}`), 팀 갱신은 API-005(`{team}`)를 행 순서대로 1건씩 호출한다(동시 호출하지 않음. 문서 서비스 호출 제한과 순서 보장 때문). API-004는 행마다 멱등 키를 하나 만들고(업로드 작업 ID + 정규화 메일계정), 다시 시도할 때도 같은 키를 쓴다. API-005는 같은 값을 다시 보내도 결과가 같다 |
| 진행 표시 | 진행 막대(높이 8) + "n / N명 등록 중" `label` 고정폭 숫자 + 현재 행 이름. 스크린리더에는 10건 단위 또는 25% 단위로만 알린다 |
| 중단 | 보조 버튼 "중단". 진행 중인 1건이 끝난 뒤 멈추고 4단계로 간다(남은 행은 "등록 안 함"으로 표시) |
| 닫기·이탈 | 진행 중에는 × 대신 "중단"만 쓸 수 있다. 화면 이동·새로고침은 CMN-01-P01 이탈 확인을 띄운다 |
| 오류 대응 | 한 건이 실패해도 다음 행을 계속 등록한다. 문서 구조 없음(422)·문서 연결 변경처럼 이후 행도 모두 실패할 오류는 즉시 멈추고 4단계로 간다 |

## 6. 리뉴얼 검토 사항

- **현행 문제 (관찰)** — 추가 폼이 데스크톱에서 전체 화면으로 열려 빈 공간이 크고 헤더·메뉴가 사라진다(캡처). 삭제 확인 버튼이 "아니요/예"로 결과가 명확하지 않다.
- **제안** — 터치용 2줄 목록 행(태블릿 가로는 목록 + 편집 패널), 휴대폰 하단 시트·태블릿 가운데 대화상자 폼, 이메일 중복 사전 안내, 회의 참석 횟수 등 부가 정보(선택). 화면 크기 기준은 D-06(태블릿 기준, 결정)을 따른다.
- **결정 (2026-11-09)**
  - 일괄 등록은 CSV만 받는다. 외부 라이브러리 없이 브라우저 기능(`TextDecoder`)과 직접 작성한 CSV 해석으로 읽는다. 양식은 정적 CSV 파일이다.
  - CSV 열은 팀·메일계정·이름 3개다. 메일계정은 `@miinit.com`만 허용한다.
  - `@miinit.com` 제한을 1명씩 추가·수정하는 폼(PTC-01-P01)에도 적용한다. 새 회의 화면의 "+ 새 참석자"(MTG-01-F09)도 같은 폼이라 함께 적용된다.
  - 팀은 Backend에서 참석자 필드로 확장한다(사용자 결정). 필요한 계약은 7장.
- **확인 필요 (CSV 일괄 등록)**
  - 최대 행 수(제안 200)와 파일 크기(제안 1MB). 1건씩 호출하므로 200명이면 문서 서비스 응답 속도에 따라 수십 초~수 분 걸릴 수 있다(추정, 실측 필요).
  - 이미 등록된 메일계정의 이름이 파일과 다를 때 정책. 제안은 이름은 바꾸지 않고 팀만 갱신(선택)이다.
  - `@miinit.com` 제한을 Backend(API-004·005 검증)에서도 막을지. 지금은 화면에서만 막으므로 API를 직접 부르면 다른 도메인도 등록된다.
  - 이미 등록된 회사 외 주소 참석자(제한 전 등록분)를 그대로 둘지, 목록에 표시해 정리하게 할지. 지금은 그대로 둔다(회의 선택·이메일 발송에 계속 쓰인다).
  - 팀 이름 최대 길이(제안 50자)와 표기 정규화 방식.
- **확인 필요** — D-02: 로그인 허용 대상을 참석자 목록으로 정하면 이 화면이 사용자 관리 역할도 하게 된다. 이 경우 권한(D-05)과 문구를 함께 조정해야 한다.

## 7. Backend 확장 요청: 참석자 팀 (2026-11-09)

> 팀은 현재 구조에 없다. [데이터 명세](../../product/data-spec.md)의 참석자 표준 모델은 `{id,name,email}`이고 "부서 … 필드는 V1 표준 모델에 추가하지 않는다"고 적혀 있다. Backend `ParticipantCreateRequest`·`Participant`도 이름·이메일만 다룬다. 지금 `team`을 보내면 오류 없이 버려진다(Spring 기본 설정은 모르는 필드를 무시). 사용자가 Backend에서 팀을 확장하기로 결정했다. 아래는 화면이 기대하는 계약이다. 고정 제약(기존 API 변경 안 함)의 예외이므로 [리뉴얼 준비](../README.md)에 기록했다. 확장이 반영되면 [API 명세](../../product/api-spec.md)·데이터 명세를 고친다.

| 대상 | 화면이 기대하는 계약 |
|---|---|
| 표준 모델 | `{id, name, email, team}`. `team`은 문자열 또는 `null`(팀 없음). 기존 참석자는 `null` |
| API-003 목록 | 항목마다 `team` 포함(없으면 `null`). **팀 정보가 없거나 해석할 수 없어도 목록 전체를 실패시키지 않는다**(지금은 필수 값 해석 실패 시 `PARTICIPANT_LIST_FAILED`이므로, 기존 문서가 깨지지 않게 팀은 선택 값으로 다룸) |
| API-004 추가 | 요청 `{name, email, team?}`. `team`은 앞뒤 공백 제거, 빈 문자열은 `null`, 최대 길이 초과는 400 `VALIDATION_FAILED`. 멱등 비교(같은 키·같은 payload)에 `team`을 포함한다. 응답에 `team` 포함 |
| API-005 수정 | `team`만 보내는 요청 허용. `team: null`은 팀 지우기. 나머지 규칙은 현행과 같다 |
| 문서 서비스 저장 | 참석자 페이지 본문에 `Email: …` 다음 줄로 `Team: …`을 기록하고 읽는다(Notion·Confluence 공통). 줄이 없으면 `null` |
| 문서 서비스 전환 (SET-06) | 전체 복사 시 팀도 옮긴다(`TransferPageCodec` 등 전환 기록 형식 포함) |
| 이메일 도메인 | CSV 일괄 등록과 추가·수정 폼(P01) 모두 화면에서 `@miinit.com`만 받는다. 팀 확장과 함께 API에서도 막을지는 확인 필요(6장) |
| 쓰지 않는 곳 | 회의 목록·상세(API-017·018)의 `participants:[{id,name}]`, 회의 roster, 화자 매핑 응답에는 팀이 필요 없다(바꾸지 않음) |

**Frontend 준비 방식**

- 참석자 타입에 `team?: string | null`을 둔다. 응답에 `team`이 없으면(확장 배포 전) 팀 열·팀 거르기·팀 입력·CSV 팀 반영·"팀 갱신"을 숨기고, CSV의 팀 열은 읽기만 한다. 확장 배포 뒤에는 코드 변경 없이 보이게 한다.
- Backend 확장이 PTC 묶음보다 늦어지면 이 방식으로 먼저 공개할 수 있다. 같이 배포할지는 PTC 묶음 착수 때 정한다.
