# SET-03 문서 서비스 선택

| 항목 | 내용 |
|---|---|
| 화면 ID | SET-03 |
| 유형 | 페이지 (마법사 1단계) |
| 경로 | `/setup/document` (최초 연결), `/settings/document` (변경 모드) |
| 현재 구현 | `frontend/src/DocumentSetupWizard.tsx` (서비스 미선택 상태) |
| 진입 조건 | 로그인(신규). 문서 연결이 없어 CMN-04에서 이동, SET-02 "문서 서비스 변경", HOME-01-P01 "문서 연결 변경" |
| 연결 화면 | 서비스 선택 → SET-04 / 문서 서비스 설정으로 돌아가기 → SET-02 (연결 있을 때) |
| 사용 API | API-023 문서 설정 상태 |
| 현행 캡처 | [문서 서비스 연결](<../현_UI/문서 서비스 연결.png>) (최초), [문서 연결 변경](<../현_UI/문서 연결 변경.png>) (변경) |

## 1. 화면 개요

회의록을 저장할 문서 서비스(Notion 또는 Confluence Cloud)를 고른다. 처음 연결할 때와 바꿀 때 같은 화면을 쓴다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| SET-03-F01 | 서비스 선택 | Notion / Confluence | 선택 시 SET-04로 진행, 이전 입력 초기화 |
| SET-03-F02 | 현재 연결 안내 | 변경 모드일 때 | "현재 {서비스}에 연결되어 있습니다. 변경할 문서 서비스를 선택해 주세요." |
| SET-03-F03 | 현재 연결 요약 | 연결이 있을 때 | 현행: "문서 서비스 / 현재 연결: … / 연결 버전: n" 카드 |
| SET-03-F04 | 돌아가기 | 변경 취소 | 문서 서비스 설정으로 돌아가기 → SET-02 |
| SET-03-F05 | 진행 중 작업 우선 | 진행·실패 작업이 있으면 | 선택 대신 SET-05 표시 |

## 3. 화면 구성 요소

### 3.1 단계 표시 (제안)

마법사 상단에 `① 서비스 선택 → ② 연결 정보 → ③ 문서 생성` 단계 표시를 둔다. 변경 모드는 `③ 자료 이전 → ④ 전환`까지 표시한다.

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 머리 | 제목 | 제목 | 최초: 문서 서비스 연결 / 변경: 문서 서비스 선택 |
| | 설명 | 텍스트 | 최초: "연결된 문서 서비스가 없습니다. 회의록을 저장하려면 먼저 서비스를 연결해 주세요." |
| | 단계 표시 | 단계 표시기 | **제안** |
| 선택 | 서비스 카드 ×2 | 선택 카드(버튼) | 아이콘, 이름, 설명("Notion에 연결"), → 화살표. **제안**: 설명을 "Notion 페이지에 회의록을 저장합니다"처럼 구체화, 현재 연결된 서비스에 "현재 사용 중" 배지 |
| 하단 | 문서 서비스 설정으로 돌아가기 | 링크 | 연결이 있을 때만 |

## 4. 상태별 화면

| 상태 | 표시 |
|---|---|
| 불러오는 중 | "문서 설정을 불러오는 중…" |
| 조회 실패 | "문서 연결 상태를 확인할 수 없습니다" + 다시 불러오기 |
| 저장소 사용 불가 | SET-02와 같은 안내 |
| 최초 연결 | 서비스 카드 2개 |
| 변경 모드 | 안내 문구 + 현재 연결 요약 + 서비스 카드 |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)** — 변경 화면 캡처에서 이전 연결 완료 카드(단계 표시와 "확인" 버튼)가 서비스 선택 위에 그대로 남아 있다. 코드상 마지막 초기화 작업(`INITIALIZE`, `SUCCEEDED`)이 문서 설정 상태에 남아 있으면 완료 카드를 계속 그리는 조건으로 보인다(추정, 실제 재현 확인 필요). 리뉴얼 시 단계별 표시 조건과 상태 초기화 규칙을 명확히 해야 한다.
- **제안** — 마법사 단계 표시, 서비스별 특징(필요 정보, 권한) 짧은 비교.
- **확인 필요** — HOME-01-P01의 "문서 연결 변경"이 `/setup/document`(이 화면, 비설정 모드)로 이동하는데, 코드상 이 경로에서는 연결 있는 상태의 변경이 끝까지 진행되지 않는 것으로 보인다(추정). 변경 진입점을 SET-02로 통일할지 결정한다.
