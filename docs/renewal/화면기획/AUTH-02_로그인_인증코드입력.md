# AUTH-02 로그인 — 인증 코드 입력 (신규)

| 항목 | 내용 |
|---|---|
| 화면 ID | AUTH-02 |
| 유형 | 페이지 (인증 전용 레이아웃) |
| 경로 | `/login/verify` (제안) |
| 현재 구현 | 없음 — 신규 |
| 진입 조건 | AUTH-01에서 코드 발송 성공 (이메일 정보가 없으면 AUTH-01로 되돌림) |
| 연결 화면 | 성공 → 원래 경로 또는 HOME-01 (문서 미연결이면 CMN-04 → SET-03) / 이메일 변경 → AUTH-01 |
| 사용 API | **신규 필요**: 코드 검증·세션 발급 (예: `POST /auth/otp/verify`), 코드 재발송 (`POST /auth/otp/request`) — D-01 |
| 현행 캡처 | 없음 |

## 1. 화면 개요

이메일로 받은 6자리 숫자 코드를 입력해 로그인을 완료한다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| AUTH-02-F01 | 발송 대상 표시 | 코드를 보낸 이메일 표시 | 일부 마스킹 여부 확인 필요 (예: `na**@company.com`) |
| AUTH-02-F02 | 코드 입력 | 6자리 숫자 입력 | 숫자만 허용. 6칸 분리 입력(제안) — 입력 시 다음 칸 자동 이동, Backspace로 이전 칸 이동 |
| AUTH-02-F03 | 붙여넣기 | 메일에서 복사한 코드 붙여넣기 | 6자리를 각 칸에 자동 분배. 공백·하이픈 제거 |
| AUTH-02-F04 | 자동 입력 | 모바일 OS의 코드 자동 완성 | `inputmode=numeric`, `autocomplete=one-time-code` |
| AUTH-02-F05 | 자동 제출 | 6자리가 모두 채워지면 자동 검증 | 검증 중 입력 잠금. 확인 버튼도 함께 제공 |
| AUTH-02-F06 | 유효시간 표시 | 코드 만료까지 남은 시간 | mm:ss 카운트다운. 만료되면 입력 비활성 + 재발송 유도 (유효시간 D-04) |
| AUTH-02-F07 | 코드 재발송 | 새 코드 요청 | 재발송 대기 시간 동안 비활성("{n}초 후 재발송"). 재발송 시 이전 코드 무효, 입력 초기화 |
| AUTH-02-F08 | 시도 제한 | 틀린 코드 반복 입력 차단 | 남은 시도 횟수 표시. 초과 시 잠금 안내 후 AUTH-01로 (횟수 D-04) |
| AUTH-02-F09 | 이메일 변경 | 다른 이메일로 다시 시작 | AUTH-01로 이동, 입력했던 이메일 채워 둠 |
| AUTH-02-F10 | 로그인 유지 | 마지막 활동 후 2시간 유지 | 사용자 조작(누르기·입력 등), 페이지 이동, 녹음 진행이 있을 때마다 만료 시각을 지금부터 2시간 뒤로 갱신한다. 활동 없이 2시간이 지나면 다시 로그인한다. 로그인 유지 체크박스는 두지 않는다 (D-04 결정). 만료 시 처리는 CMN-01-F09를 따른다 |
| AUTH-02-F11 | 로그인 완료 이동 | 세션 발급 후 이동 | AUTH-01에서 보관한 원래 경로 → 없으면 HOME-01 |

## 3. 화면 구성 요소

화면 기준은 마이크가 있는 태블릿이다. PC 전용 배치는 만들지 않는다(D-06). 크기·글자·컴포넌트 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 8장을 따른다. 인증 화면은 AUTH-01과 같은 인증 전용 레이아웃(메뉴·상단 바 없음, 가운데 카드)을 쓴다.

### 3.1 태블릿 (기준, 폭 600px 이상)

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│        ┌──────────────────────────────────┐          │
│        │     [Downforce Minutes 로고]       │          │
│        │                                  │          │
│        │  인증 코드 입력                     │ headline │
│        │  name@company.com 으로 보낸        │          │
│        │  6자리 코드를 입력해 주세요.          │ body     │
│        │  [이메일 변경]                      │ 텍스트 버튼│
│        │                                  │          │
│        │  ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐   │ 칸 사이 8 │
│        │  │ 1│ │ 2│ │ 3│ │  │ │  │ │  │   │          │
│        │  └──┘ └──┘ └──┘ └──┘ └──┘ └──┘   │          │
│        │  남은 시간 04:32                   │ caption  │
│        │  (오류 메시지 · 남은 시도 n회)        │ caption  │
│        │                                  │          │
│        │  [             확인             ]  │ lg 56    │
│        │                                  │          │
│        │  코드를 받지 못했나요?               │          │
│        │  [코드 다시 받기 (52초)]             │ 텍스트 버튼│
│        │  스팸함도 확인해 주세요.              │ caption  │
│        └──────────────────────────────────┘          │
└──────────────────────────────────────────────────────┘
 태블릿 세로 약 820px, 메뉴 없음
```

| 영역 | 요소 | 유형 | 내용·규칙 | 필수 |
|---|---|---|---|---|
| 배경 | 인증 레이아웃 | 레이아웃 | AUTH-01과 같다. 배경 `bg`, 가운데 카드(테두리 `border`, `radius-lg`, 안쪽 여백 24). 카드 최대 폭은 AUTH-01과 같이 **확인 필요** (제안: 480px) | - |
| 머리 | 로고, 제목 | 이미지·제목 | 인증 코드 입력. 로고는 Downforce Minutes(다운포스 CI, D-10), 제목 `headline`(태블릿 28/36) | - |
| | 안내 문구 | 텍스트 | `{이메일}`으로 보낸 6자리 코드를 입력해 주세요. `body`, `text-muted`. 이메일 부분은 `text` 색 | - |
| | 이메일 변경 | 텍스트 버튼 | AUTH-01 이동. 글자 `label`, 링크 색(`primary-hover`, blue-700). 누르는 영역 높이 48 이상 | - |
| 입력 | 코드 입력 6칸 | 숫자 입력 그룹 | 그룹 라벨 "인증 코드 6자리", 각 칸 1자리, 첫 칸 자동 초점. 각 칸 `inputmode=numeric`(숫자 키패드), `autocomplete=one-time-code`(첫 칸), 글자 16px 이상, 고정폭 숫자(`tabular-nums`), 테두리 `border-input`, 초점 칸 `focus` 색, 모서리 `radius-md`. 칸 크기는 **확인 필요** (제안: 입력란 높이와 맞춰 태블릿 52×52 / 휴대폰 48×48, 칸 사이 8, 숫자 글자는 `title` 크기) | 필수 |
| | 남은 시간 | 타이머 | `caption`, 고정폭 숫자(`tabular-nums`). 1분 미만이면 강조 색(`danger-soft` 글자색 red-700) + 시계 아이콘(색만으로 구분하지 않음). 스크린리더에는 매초가 아니라 구간별로만 알림 | - |
| | 오류 메시지 | 텍스트 | 입력 그룹 아래 `caption`, red-700 + 오류 아이콘. 오류 칸 테두리 `danger`. 오류 시 칸 흔들림 효과(동작 줄이기 설정 시 생략) | - |
| 실행 | 확인 | 주 버튼 | 버튼 `lg`(높이 56), `primary` 색, 카드 폭 가득. 6자리 미만이면 비활성. 검증 중 로딩 | - |
| 보조 | 코드 다시 받기 | 텍스트 버튼 | 링크 색(`primary-hover`), 누르는 영역 높이 48 이상. 대기 시간 중 비활성(neutral-400 이하 색 + `aria-disabled`) + 남은 초 표시(`tabular-nums`) | - |
| | 스팸함 안내 | 텍스트 | `caption`, `text-muted` | - |
| 알림 | Toast | 알림 | 재발송 완료 등. 화면 하단 가운데, 최대 폭 480 | - |

- 숫자 키패드가 열려 높이가 560px 이하(`short`)가 되면 로고를 줄이거나 숨기고 위아래 여백을 줄여 코드 칸과 확인 버튼이 키패드 위에 보이게 한다.

### 3.2 태블릿 가로 (폭 960px 이상)

세로 배치를 그대로 쓰고 카드를 화면 가운데에 둔다. 넓은 화면(PC 포함)도 같다.

### 3.3 휴대폰 (폭 600px 미만)

- 카드 테두리 없이 화면 전체를 1단으로 쓴다. 좌우 여백 16px, 위쪽 안전 영역만큼 띄운다. 제목은 `headline` 휴대폰 크기(24/32).
- 코드 6칸은 한 줄을 유지한다. 폭 360px 휴대폰에서 본문 폭은 328px(360 − 좌우 16×2)이므로 칸 48px × 6 + 사이 8px × 5 = 328px로 딱 맞는다. 더 좁은 화면은 칸 사이 간격을 줄인다(**확인 필요**: 360px 미만은 지원 대상 밖, 8.1).
- 확인 버튼은 코드 칸 아래에 화면 폭 가득 배치한다. 하단 탭 바가 없는 화면이므로 하단 고정하지 않는다.
- 숫자 키패드가 열린 `short` 상태에서는 로고를 숨기고 "코드를 받지 못했나요?"·스팸함 안내는 확인 버튼 아래(스크롤 영역)로 둔다.
- Toast는 화면 하단에서 16px + 하단 안전 영역만큼 띄운다(탭 바 없음).

## 4. 상태별 화면

| 상태 | 조건 | 표시 |
|---|---|---|
| 기본 | 진입 직후 | 빈 6칸, 타이머 시작, 재발송 대기 중 |
| 검증 중 | 6자리 입력 또는 확인 클릭 | 입력 잠금, 버튼 로딩 |
| 코드 불일치 | 서버 거절 | 칸 초기화 + 첫 칸 초점, "코드가 올바르지 않습니다. (남은 시도 n회)" |
| 만료 | 타이머 0 또는 서버 만료 응답 | 입력 비활성, "코드가 만료되었습니다. 새 코드를 받아 주세요.", 재발송 버튼 강조 |
| 시도 초과 | 서버 잠금 응답 | 오류 안내 + "처음으로" 버튼(AUTH-01) |
| 재발송 완료 | 재발송 성공 | Toast "새 인증 코드를 보냈습니다.", 타이머 초기화 |
| 성공 | 세션 발급 | 짧은 성공 표시 후 이동 |
| 네트워크 오류 | 요청 실패 | 상단 오류 배너, 입력값 유지 |

## 5. 메시지 (초안)

| 구분 | 문구 |
|---|---|
| 불일치 | 코드가 올바르지 않습니다. 다시 확인해 주세요. (남은 시도 {n}회) |
| 만료 | 코드가 만료되었습니다. 새 코드를 받아 주세요. |
| 시도 초과 | 시도 횟수를 초과했습니다. 잠시 후 처음부터 다시 시도해 주세요. |
| 재발송 | 새 인증 코드를 보냈습니다. |

## 6. 리뉴얼 검토 사항

- **보안 (제안)** — 코드는 화면·주소·브라우저 저장소에 남기지 않는다. 세션은 `HttpOnly` 쿠키 방식을 권장한다(Frontend 스크립트에서 토큰을 읽지 않도록). Vercel 리라이트(`/api/backend`)를 거치므로 같은 출처 쿠키로 운용 가능한지 Backend와 확인이 필요하다.
- **결정 (D-04, 2026-11-06)**
  - 코드 유효시간 5분, 재발송 간격 50초, 틀린 코드 허용 5회(초과 시 AUTH-01로).
  - 로그인 유지: 마지막 활동(조작·페이지 이동·녹음 중) 후 2시간. 활동이 있으면 만료 시각을 갱신한다. 녹음하는 동안은 계속 갱신한다.
  - 로그아웃하면 세션을 바로 지운다. 다시 로그인할 때 새 세션을 만든다.
- **구현 참고 (제안)** — 기존 API에는 인증을 적용하지 않으므로(D-01) 서버는 일반 API 호출로 활동을 알 수 없다. 화면 이동·조작 시 Frontend가 세션 확인 API를 불러 만료 시각을 갱신한다. 호출이 잦지 않도록 일정 간격(예: 1분)으로 묶는다.
- **진행 중 작업** — 녹음 중은 활동으로 보고 만료 시각을 계속 갱신한다(결정). 그 밖의 진행 중 작업이 있을 때 만료되면 CMN-01-F09에 따라 바로 로그인 화면으로 보내지 않는다.
- **확인 필요 (크기)** — 코드 입력 칸 크기(제안: 태블릿 52×52 / 휴대폰 48×48, 숫자 `title` 크기), 인증 카드 최대 폭(제안: 480px). 8장에 기준이 없다. 탭 바가 없는 화면의 휴대폰 Toast 위치(제안: 하단 16px + 안전 영역)도 8장 기준(탭 바 위 16)을 준용한 것이다.
