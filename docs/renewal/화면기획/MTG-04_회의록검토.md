# MTG-04 회의록 검토

| 항목 | 내용 |
|---|---|
| 화면 ID | MTG-04 |
| 유형 | 페이지 (편집) |
| 경로 | `/meetings/:sessionId/review` |
| 현재 구현 | `frontend/src/ReviewSpeakerPage.tsx`, `ReviewMinutesEditor.tsx`, `ReviewTranscriptDrawer.tsx` |
| 진입 조건 | MTG-03 처리 완료 후 자동 이동 (세션 상태 `REVIEW`) |
| 연결 화면 | 발송 → MTG-05 / 뒤로 → MIN-01 / Review 상태 아님 → MTG-03 / 참석자 없음 → PTC-01 |
| 하위 팝업 | MTG-04-P01 전사 원문, MTG-04-P02 검토 알림 |
| 사용 API | API-010 검토 데이터, API-001 앱 설정, API-003 참석자, API-011 화자 매핑 저장, API-012 회의록 저장, API-014 검토 확정, API-015 문서 저장·전달 시작 |
| 현행 캡처 | 없음 |

## 1. 화면 개요

자동 생성된 회의록 초안을 항목별로 고치고, 화자(Speaker A/B…)를 실제 참석자와 연결한 뒤, 문서 서비스에 저장하고 참석자에게 알린다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| MTG-04-F01 | 회의 요약 편집 | 여러 줄 입력 | - |
| MTG-04-F02 | 목록 항목 편집 | 논의 내용, 결정 사항, 후속 조치 | 항목 추가·삭제·수정. 빈 항목은 오류 |
| MTG-04-F03 | 실행 항목 편집 | 할 일, 담당자, 기한 | 할 일 필수. 담당자는 이 회의 참석자 중 선택. 기한은 올바른 날짜 |
| MTG-04-F04 | 회의록 저장 | 변경사항 저장 | 변경이 있고 유효할 때만. 서버 버전 충돌 시 최신 내용을 불러오고 수정 내용은 유지 |
| MTG-04-F05 | 화자 매핑 | 화자별로 참석자 선택 | **변경 (2026-11-09):** 접는 영역·선택 상자가 아니라 화자별 매핑 카드(3.7)에서 참석자 칩을 한 번 눌러 고른다. 전사 원문을 열지 않고 매핑을 끝낼 수 있어야 한다. 선택 즉시 자동 저장(API-011). 실패 시 카드에 "다시 저장" |
| MTG-04-F12 | 화자별 발화 미리보기 | 화자를 알아볼 수 있는 대표 발화 표시 | **요구사항 (2026-11-09).** 카드마다 대표 발화 3개(시각 + 문장)와 발화 통계(횟수·말한 시간·비율)를 보인다. API-010 `transcript`의 segment(`speakerId`, `startMs`, `endMs`, `text`)로 화면에서 계산한다(추가 API 없음). "발화 더 보기"로 카드 안에서 최대 10개까지 펼친다 |
| MTG-04-F06 | 전사 원문 보기 | 화자·시간·발화 목록 | MTG-04-P01. 매핑한 참석자 이름으로 표시 |
| MTG-04-F07 | 문서 저장 및 참석자 알림 발송 | 검토 확정 → 문서 저장·전달 시작 | 저장 안 된 변경, 저장 중, 매핑 미저장, 문서 연결 미준비 시 MTG-04-P02로 안내하고 중단. 성공 또는 결과 불명확 시 MTG-05 이동 |
| MTG-04-F08 | 발송 대상 | 이메일 대상 결정 | 회의 참석자 전원에게 이메일. 화면에서 선택하지 않는다(D-07 결정). Slack 알림은 폐기했다(D-11) |
| MTG-04-F09 | 재생성 진행 표시 | 다른 템플릿 재생성이 진행 중일 때 | 진행 막대 + 완료 시 최신 회의록 표시 |
| MTG-04-F10 | 이탈 방지 | 저장 안 된 변경·저장 중 | CMN-01-P01 |
| MTG-04-F11 | 다른 템플릿으로 다시 생성 | API-013 | **미연결 구현** (`MinutesRegenerationControl.tsx`). 포함 여부 D-07 |

## 3. 화면 구성 요소

### 3.1 태블릿 (기준, 폭 600px 이상)

화면 기준은 마이크가 있는 태블릿 세로(폭 820px 전후)다. 공통 틀(내비게이션 레일 88px, 상단 바 64px)은 CMN-01을 따르고, 크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4·8장을 따른다. 세로 화면은 1단으로 편집하고, 전사 원문은 오른쪽에서 열리는 시트(MTG-04-P01)로 본다.

```
┌──────┬──────────────────────────────────────────────┐
│ [로고]│ ← 회의록 검토 · 주간 회의  [저장됨 ✓] [전사 원문] │  상단 바 64px
│      ├──────────────────────────────────────────────┤
│  ⌂   │ 화자 매핑                 3명 중 2명 지정 ▓▓▓░  │  title + 진행
│  홈   │ ┌ ● 화자 A ── 발화 18회·6분 (41%) ┐ ┌ ● 화자 B ─ 12회·4분 ┐│
│  ▤   │ │ [홍길동 ✓]                     │ │ [미지정 ⚠]         ││  상태
│ 회의록 │ │ 00:12 이번 주 배포 일정부터 …    │ │ 01:40 IAM 권한은 … ││  대표 발화 3개
│  👥  │ │ 03:05 QA는 목요일까지 …          │ │ 04:22 저는 반대 …   ││
│ 참석자 │ │ 07:41 그럼 그렇게 정리할게요      │ │ 09:10 다음 주에 …   ││
│  ⚙   │ │ 발화 더 보기                     │ │ 발화 더 보기        ││
│  설정  │ │ [홍길동✓][김철수][이영희][미지정]  │ │ [홍길동 A][김철수]… ││  참석자 칩 (한 번 눌러 지정)
│      │ └───────────────────────────────┘ └──────────────────┘│
│      │ ┌ ● 화자 C ── …                   ┐                    │  2열 카드
│      │ 회의 요약                              [접기]  │
│ 참석자 │ [ 여러 줄 입력 (내용만큼 높이 늘어남)       ]  │
│  ⚙   │ 논의 내용                            [+ 추가]  │
│  설정  │ [ 항목 1                              ] [×]  │
│      │ 결정 사항                            [+ 추가]  │
│      │ 실행 항목                            [+ 추가]  │
│      │ ┌ 할 일 [                          ]   [×] ┐   │
│      │ │ 담당 [홍길동     ▾]  기한 [2026-11-12  ]  │   │
│      │ └────────────────────────────────────────┘   │
│      │ 후속 조치                            [+ 추가]  │
│      ├──────────────────────────────────────────────┤
│  [👤] │ [변경사항 저장]   [문서 저장 및 참석자 알림 발송] │  하단 실행 바 (고정)
└──────┴──────────────────────────────────────────────┘
 레일 88px
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 바 (높이 64px) | 뒤로 가기 | 아이콘 버튼 48×48 | MIN-01 ("회의록 목록으로") |
| | 제목 | 제목(h1) | 회의록 검토 (+ 회의 제목, 제안). `headline`, 길면 한 줄 말줄임 |
| | 저장 상태 | 상태 표시 | 저장 중 / 저장됨 / 저장 안 된 변경 있음 (제안). 아이콘 + 문구(`caption`)로 표시하고 색만으로 구분하지 않는다. 저장됨 `text-muted`, 저장 안 된 변경 `warning-soft`, 저장 실패 `danger-soft` |
| | 전사 원문 | 보조 버튼 `md` 48 | MTG-04-P01 열기 (세로 화면). 가로 화면(960px 이상)에서는 오른쪽 패널에 상시 표시하므로 숨긴다 |
| | 새 회의 (CMN-01 공통) | 주 버튼 | 이 화면에서는 숨기는 것을 제안한다. 하단 "문서 저장 및 참석자 알림 발송"과 주 버튼이 둘이 되기 때문이다. **확인 필요**: CMN-01 상단 바 "새 회의" 숨김 화면(현재 녹음·처리 화면)에 이 화면을 추가할지 |
| 화자 매핑 (편집 영역 위, 접지 않음) | 구역 머리 | 제목 + 진행 | "화자 매핑"(`title`) + "n명 중 m명 지정"(`label`, 고정폭 숫자) + 진행 막대(높이 8). 설명: "발화를 보고 화자가 누구인지 골라 주세요. 고른 이름이 전사 원문과 회의록에 표시됩니다."(`caption`, `text-muted`) |
| | 화자 매핑 카드 | 카드 × 화자 수 | **변경 (2026-11-09):** 3.7을 따른다. 태블릿 세로는 **2열 그리드**(카드 사이 16), 화자가 1명이면 1열. 접기 버튼을 두지 않는다. 현행의 접힌 영역·선택 상자는 쓰지 않는다 |
| | 카드 순서 | 정렬 | 말한 시간이 긴 화자부터. 매핑해도 순서를 바꾸지 않는다 |
| | 미지정 안내 | 안내 | 미지정 화자가 있으면 "문서 저장 및 참석자 알림 발송"을 누를 때 MTG-04-P02로 "미지정 화자 n명은 '화자 A'처럼 라벨로 저장됩니다. 계속할까요?"를 안내한다(차단하지 않음. API-014는 미지정을 허용) |
| 회의록 편집 | 설명 | 텍스트 | 생성된 회의 내용을 항목별로 검토하고 수정합니다. (`caption`, `text-muted`) |
| | 섹션 제목 | 제목(h2) | `title`. 오른쪽에 "+ 추가" 보조 버튼 `sm` 40(누르는 영역 48) |
| | 회의 요약 | 섹션 + 여러 줄 입력 | 접고 펼치기(접기 버튼은 항상 보이는 아이콘 버튼 48×48). 입력 글자 `body` 16px(16px 미만이면 iPad·iPhone이 자동 확대). 입력란은 내용만큼 높이가 늘어난다(제안). 최소 높이는 **확인 필요**(제안: 3줄 분량) |
| | 논의 내용·결정 사항·후속 조치 | 섹션 + 항목 목록 | 항목별 여러 줄 입력(최소 높이 52px, 내용만큼 늘어남), 삭제 ×는 항상 보이는 아이콘 버튼 48×48(hover로만 나타나지 않음), + 추가, 빈 항목 오류 "내용을 입력해 주세요."(입력란 아래 `caption`, red-700 글자 + 오류 아이콘, 입력란 테두리 `danger`) |
| | 실행 항목 | 섹션 + 카드 목록 | 할 일(필수), 담당자 선택("담당자 선택"/참석자/"기존 담당자 유지"), 기한 날짜, × 삭제, + 추가. 태블릿 세로: 1행 할 일 + ×, 2행 담당·기한 2칸. 입력란 높이 52px, 카드 사이 12px |
| | 항목 사이 간격 | 간격 | 요소 사이 8/12/16, 구역 사이 32(휴대폰 24) |
| 실행 (하단 고정 바) | 회의록 변경사항 저장 | 보조 버튼 `md` 48 (`primary-soft`) | 변경 + 유효할 때 활성 |
| | 문서 저장 및 참석자 알림 발송 | 주 버튼 `lg` 56 (`primary`) | 처리 중 "문서 저장 및 참석자 알림 처리 중…" |
| | 저장 결과 다시 확인 | 보조 버튼 `md` 48 | 저장 결과가 불명확할 때 |
| | 고정 바 | 영역 | 흰 배경 + 위쪽 구분선 `border`, 하단 안전 영역만큼 띄운다. 편집 영역 끝에 고정 바 높이만큼 여백을 두어 마지막 입력란이 가려지지 않게 한다. 바 높이는 버튼 56 + 위아래 여백으로 정해지며 고정값은 **확인 필요**(제안: 위아래 12px) |

- **터치 키보드 편집 (태블릿)**
  - 세로 화면은 화면 키보드가 열려도 남은 높이가 560px보다 커서 `short`에 걸리지 않는다. 하단 실행 바는 유지하되, 초점이 간 입력란이 키보드나 실행 바에 가리지 않도록 화면을 스크롤한다.
  - iPad Safari에서 키보드가 열린 상태의 고정 요소 위치는 기기마다 다를 수 있어 **확인 필요**하다(Safari 자동 테스트 제외, S-08).
  - 긴 글은 입력란 안에서 따로 스크롤하지 않고 입력란 높이를 늘려 페이지 스크롤 하나로 읽고 고치게 한다(제안).

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 왼쪽 단 | 회의록 편집 | 영역 | 3.1 편집 영역과 같다. 하단 실행 바는 왼쪽 단 아래에 고정한다 |

| | 패널 폭 | 배치 | 384px 고정, 나머지를 편집 단에 배정 (스타일 방식 검토 8.6 보조 크기). 384 폭에서 참석자 칩은 2~3개씩 줄바꿈된다 |
| 공통 | 스크롤 | 규칙 | 두 단은 각각 따로 스크롤한다. 상단 바와 하단 실행 바는 고정 |
| | 좌우 여백 | 간격 | 32px (8.4 태블릿 가로) |

- 본문 최대 폭 1040px을 넘는 화면은 2단 전체를 가운데 정렬한다.

### 3.3 휴대폰 (폭 600px 미만)

- **배치:** 1단. 상단 바(높이 56px)에 뒤로 가기, 제목(한 줄 말줄임), 저장 상태 아이콘, 전사 원문 아이콘 버튼(48×48)을 둔다. 하단 탭 바는 CMN-01을 따른다.
- **화자 매핑:** 편집 영역 위에 3.7 매핑 카드를 **1열**로 쌓는다(접지 않음). 대표 발화는 2개만 보이고 "발화 더 보기"로 펼친다. 참석자 칩은 폭에 맞춰 줄바꿈한다.
- **실행 항목 카드:** 할 일, 담당, 기한을 한 줄에 하나씩 쌓는다. 삭제 ×는 카드 오른쪽 위 아이콘 버튼 48×48.
- **전사 원문:** MTG-04-P01을 화면 전체를 덮는 시트로 연다. 상단에 제목과 닫기, 발화는 `body-lg`(17/28).
- **하단 실행:** "문서 저장 및 참석자 알림 발송"은 주 버튼 `lg` 56으로 하단 탭 바 위에 화면 폭 가득 고정하고, 하단 안전 영역만큼 띄운다. "회의록 변경사항 저장"은 같은 고정 영역 안에 보조 버튼으로 두면 고정 영역이 커져 편집 공간이 줄어든다. **확인 필요**(제안: 주 버튼 왼쪽에 보조 버튼 `md` 48을 나란히 두거나, 상단 바 저장 상태 옆으로 옮김).
- **대화상자:** MTG-04-P02와 발송 전 확인(제안)은 하단 시트(폭 가득, 최대 높이 90%, 모서리 `radius-xl` 20)로 연다.
- **키보드가 열린 상태(`short`, 높이 560px 이하):** 상단 바와 여백을 줄이고, 하단 고정 실행 바는 본문 끝으로 옮긴다. 저장 상태는 상단 바에 계속 표시해, 키보드를 닫지 않아도 저장 여부를 알 수 있게 한다.
- **보이는 양:** 휴대폰 세로(360×780 기준)는 키보드가 열리면 입력란 1~2개만 보인다(추정). 긴 요약은 입력란 높이를 늘려 페이지 스크롤로 고친다.

### 3.4 PC

- 고려하지 않는다(D-06). 넓은 화면에서는 3.2 태블릿 가로 배치를 본문 최대 폭 1040px로 가운데 정렬한다.
- 삭제·추가·접기 버튼은 항상 보이게 두고, 마우스 hover에서만 나타나는 동작은 만들지 않는다.

### 3.7 화자 매핑 카드 (요구사항, 2026-11-09)

전사 원문을 열지 않고 카드만 보고 "이 화자가 누구인지" 판단해 한 번에 지정하게 한다. 화자 1명당 카드 1장이다.

```
┌──────────────────────────────────────────────┐
│ ● 화자 A        발화 18회 · 6분 12초 (41%)       │  머리: 화자 색 점 + 라벨 + 통계
│ [✓ 홍길동]  저장됨                              │  현재 지정 상태 + 저장 상태
│ ─────────────────────────────────────────── │
│ 00:12  이번 주 배포 일정부터 정리하고 넘어갈게요.   │  대표 발화 (2줄까지, 말줄임)
│ 03:05  QA는 목요일까지 끝내는 걸로 하고 금요일에…  │
│ 07:41  그럼 결정 사항은 그렇게 정리할게요.          │
│ 발화 더 보기 (15)                원문에서 보기 →    │  텍스트 버튼 2개
│ ─────────────────────────────────────────── │
│ 이 화자는                                       │
│ [✓ 홍길동] [김철수 · B] [이영희] [박민수] [미지정]  │  참석자 칩 (단일 선택)
└──────────────────────────────────────────────┘
```

| 영역 | 요소 | 내용·규칙 |
|---|---|---|
| 카드 | 면 | 흰 면 `bg-bg`, `radius-xl`, `shadow-card`(시안 적용 기준 3.3), 안쪽 여백 20(휴대폰 16). 미지정 카드는 왼쪽 위 상태 배지로 구분하고 테두리 색만으로 구분하지 않는다 |
| 머리 | 화자 표시 | 화자 색 점(지름 12) + "화자 A"(`label`). 화자 색은 전사 원문의 화자 표시와 같은 색을 쓴다(장식, 대비 기준 예외. 라벨 글자가 함께 있음). 서버 라벨(`speaker_a`)은 "화자 A"처럼 바꿔 표시한다(R-09 용어 확정 전 제안) |
| | 통계 | "발화 n회 · m분 s초 (p%)" `caption`, `text-muted`, 고정폭 숫자. 말한 시간 = 그 화자 segment의 (`endMs` − `startMs`) 합. 비율 = 전체 발화 시간 대비 |
| | 지정 상태 | 지정됨: `selected` 배지 "✓ {이름}". 미지정: `warning-soft` 배지 "⚠ 미지정". 옆에 저장 상태 `caption`: 저장 중(스피너) / 저장됨 / 저장 실패 + "다시 저장" 텍스트 버튼(누르는 영역 48) |
| 미리보기 | 대표 발화 | 기본 3개(휴대폰 2개). 각 줄 = 시작 시각 `mm:ss`(`caption`, 고정폭 숫자, 폭 고정) + 발화 `body`, 최대 2줄 말줄임 |
| | 고르는 규칙 | 그 화자 발화 중 10자 이상인 것에서 글자 수가 많은 순으로 고른 뒤 시각 순으로 보인다(맞장구·짧은 대답 제외). 10자 이상 발화가 모자라면 남은 칸을 앞 발화로 채운다. 화면에서 계산하며 서버에 저장하지 않는다 |
| | 발화 더 보기 | 텍스트 버튼(`link`). 카드 안에서 같은 규칙으로 최대 10개까지 펼친다. 다시 누르면 접는다(`aria-expanded`). 화면 이동 없음 |
| | 원문에서 보기 | 텍스트 버튼(`link`). 태블릿 가로: 오른쪽 패널 "전사 원문" 탭으로 바꾸고 이 화자의 첫 대표 발화로 스크롤. 태블릿 세로·휴대폰: MTG-04-P01 시트를 같은 위치로 연다. 매핑에 꼭 필요하지 않은 보조 수단이다 |
| 지정 | 참석자 칩 | "이 화자는"(`caption`) + 이 회의 참석자(roster) 칩 + 마지막에 "미지정" 칩. 단일 선택 그룹(`role="radiogroup"`, 이름 "화자 A의 참석자"), 칩마다 `role="radio"`. 칩 보이는 높이 40, 누르는 영역 48, 칩 사이 8, 폭에 맞춰 줄바꿈 |
| | 칩 모양 | 기본: 흰 면 + `border-border-input` 테두리 + 이름 `label`. 선택: `bg-primary` + 흰 글자 + ✓ 아이콘(색 + 아이콘으로 구분). 다른 화자에 이미 지정된 참석자: 칩 안에 작은 표시 "· B"(`caption`)와 스크린리더 문구 "화자 B에 지정됨". 그래도 고를 수 있다(한 사람이 둘 이상의 화자로 나뉘어 감지될 수 있음) |
| | 참석자가 많을 때 | 참석자 9명 이상이면 칩은 7명까지 보이고 "+ n명 더"를 둔다. 누르면 검색 가능한 목록을 연다(태블릿 팝오버, 휴대폰 하단 시트). 칩 순서는 이 회의 참석자 순서이고, 이미 지정된 사람을 뒤로 보내지 않는다 |
| | 동작 | 칩을 누르면 즉시 지정되고 자동 저장한다. 저장은 API-011에 모든 화자의 매핑을 함께 보낸다(API 규칙). 연달아 누르면 마지막 상태로 묶어 저장한다(제안: 마지막 입력 후 300ms). `If-Match` 버전 충돌이면 최신 매핑을 다시 불러오고 "다른 곳에서 매핑이 바뀌어 최신 상태를 불러왔습니다."를 카드 위에 보인다 |
| | 되돌리기 | 저장 후 Toast "화자 A를 홍길동으로 지정했습니다 · 되돌리기"(되돌리기 텍스트 버튼, 5초). 잘못 누른 경우를 위해서다 |
| 키보드 | 이동 | 칩 그룹 안에서는 방향키로 이동·선택하고, Tab은 다음 카드의 그룹으로 간다(라디오 그룹 표준) |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)**
  - 화자 매핑이 접힌 영역에 숨어 있고, 전사 원문은 별도 드로어로만 볼 수 있어 회의록과 원문을 함께 비교하기 어렵다.
  - "회의록 변경사항 저장"과 "문서 저장 및 참석자 알림 발송" 두 버튼의 차이가 직관적이지 않다.
  - 발송 전에 누구에게 보내는지 확인할 수 없다.
  - 용어 혼용: Minutes, Review, Speaker, 참가자/참석자.
- **제안**
  - 태블릿 가로(960px 이상) 2단 구성: 왼쪽 회의록 편집, 오른쪽 전사 원문 + 화자 매핑. 태블릿 세로·휴대폰은 1단 + 전사 원문 시트(3.1~3.3)
  - 자동 저장(입력 멈춘 뒤 저장) 또는 저장 상태 표시 강화 — 자동 저장은 서버 버전 충돌 처리 규칙과 함께 검토
  - (D-07 결정으로 제외) 발송 전 수신자 선택 확인 팝업
  - 전사 원문 검색, 발화 클릭 시 해당 위치 강조
- **요구사항 반영 (2026-11-09)** — 화자 매핑을 접는 영역에서 화자별 매핑 카드(3.7)로 바꿨다. 대표 발화 미리보기와 통계를 보고 참석자 칩을 한 번 눌러 지정하므로 전사 원문을 열지 않아도 된다. 태블릿 세로는 편집 영역 위 2열 카드, 태블릿 가로는 오른쪽 패널의 "화자 매핑" 탭, 휴대폰은 1열 카드다.
- **확인 필요 (화자 매핑)**
  - 대표 발화 고르는 규칙(10자 이상, 긴 순 3개)이 실제 회의 데이터에서 화자를 알아보기에 충분한지. 실제 전사 결과 몇 건으로 확인한다.
  - 화자별 음성 짧게 듣기는 넣지 않았다. 처리 후 오디오가 정리되고(API-009·finalize 규칙) 재생 API가 없기 때문이다. 필요하면 Backend 변경 항목으로 따로 판단한다.
  - 한 참석자를 여러 화자에 지정할 때 경고만 할지, 막을지. 제안은 허용 + 표시(API도 허용).
  - "화자 A" 표기와 "미지정" 용어(R-09, MTG 묶음 착수 때 확정).
- **확인 필요** — D-07(재생성·수신자 선택 포함 여부), 자동 저장 도입 여부, 오른쪽 패널·시트 폭, 휴대폰에서 "회의록 변경사항 저장" 버튼 위치, 이 화면의 상단 바 "새 회의" 버튼 숨김 여부. D-06(지원 화면 크기)은 태블릿 기준으로 결정됨
- **화면 크기 관련 메모** — 자동 저장을 도입하면 "회의록 변경사항 저장" 버튼이 빠져 휴대폰 하단 고정 영역 문제가 함께 해결된다.

## 6. 구현 결정 (2026-11-11, #29)

Preview에서 사용자와 조정한 구성이다. 3장과 다르면 이 장이 우선한다. 구현은 `frontend/src/review/`. 로직은 기존 `ReviewSpeakerPage.tsx`에서 `useReviewSession.ts`로 옮겼다(조회, 재생성 진행 이어 보기, 회의록 저장과 버전 충돌·결과 불명확 처리, 확정 → 문서 저장·전달).

| 요소 | 결정 |
|---|---|
| 모드 | 집중 모드(메뉴 없음). 뒤로 가기 → 회의록 목록. 새 회의부터 결과까지 메뉴 없이 이어진다 |
| 상단 바 | 제목 "회의록 검토" + **저장 버튼**(바뀐 내용이 있고 올바를 때만 누를 수 있고, 바뀌면 주 색) + 전사 원문 버튼. "저장됨" 같은 상태 글자는 두지 않는다(사용자 결정 2026-11-11: 뜻이 분명하지 않음) |
| 본문 | 탭 "화자 매핑(미지정 개수) / 회의록". 처음 열 때 미지정 화자가 있으면 화자 매핑, 없으면 회의록. 지정을 끝내도 탭은 저절로 바뀌지 않는다. 태블릿은 본문 높이를 화면에 맞추고 탭 안만 스크롤한다 |
| 화자 매핑 | 화자마다 한 줄 카드(사용자 결정 2026-11-11): **왼쪽**에 화자 색 점 + "화자 A" + 통계(발화 n회 · 말한 시간 · 비율) + 대표 발화 3개(휴대폰 2개, 10자 이상 긴 순 → 시각 순, 태블릿 `body-lg`) + 발화 더 보기(최대 10) + 원문에서 보기, **오른쪽**에 미지정 표시와 참석자 칩(하나 고르기, 다른 화자에 지정된 사람은 "· B"). 휴대폰은 위아래. 말한 시간 순, 지정해도 순서 고정 |
| 매핑 저장 | 칩을 누르면 바로 지정하고 0.3초 뒤 모든 화자 매핑을 묶어 저장(API-011). 저장 후 토스트 "화자 B: 김철수 지정 · 되돌리기". 버전 충돌(412)이면 최신 매핑을 다시 불러온다(자동 재전송 없음). 실패하면 구역 머리에 "다시 저장" |
| 회의록 구역 | 다섯 구역을 한 페이지에 쌓지 않는다(사용자 결정 2026-11-11: 항목을 추가하면 아래가 계속 밀림). 고른 구역 하나를 크게 편집한다(입력 글자 태블릿 `body-lg`). **다섯 구역 모두 같은 크기의 카드**에 담는다: 태블릿에서 카드는 발송 버튼 위까지 가득 차고, 구역을 바꿔도 크기가 같다(볼 때마다 크기가 달라 눈이 피로하지 않게). 회의 요약 입력란은 카드를 가득 채운다(긴 글은 입력란 안에서 스크롤). 목록 구역은 항목을 위에서부터 쌓고 카드 안에서만 스크롤한다. 실행 항목은 할 일 · 담당(이 회의 참석자) · 기한(큰 달력 + 지우기). 빈 항목은 입력란 아래 "내용을 입력해 주세요." |
| 발송 | 화면 아래 **가운데** 주 버튼(최대 폭 640, 휴대폰은 화면 아래 고정). 미지정 화자가 있으면 "미지정 화자 n명" 확인 대화상자(차단하지 않음). 저장 안 한 변경·저장 중·매핑 미저장·문서 연결 미준비면 "확인 필요" 대화상자(P02)로 이유를 알리고 멈춘다. 성공·결과 불명확이면 회의 결과로 간다. 받는 사람은 회의 참석자 전원, Slack 알림은 켜지 않는다(D-11) |
| 전사 원문 | 상단 바 버튼 또는 "원문에서 보기"로 대화상자를 연다(해당 발화로 스크롤·강조). 화자 이름(지정한 참석자 또는 "화자 B") + 시각 + 발화(`body-lg`) |
