# MTG-04 회의록 검토

| 항목 | 내용 |
|---|---|
| 화면 ID | MTG-04 |
| 유형 | 페이지 (편집) |
| 경로 | `/meetings/:sessionId/review` |
| 현재 구현 | `frontend/src/ReviewSpeakerPage.tsx`, `ReviewMinutesEditor.tsx`, `ReviewTranscriptDrawer.tsx` |
| 진입 조건 | MTG-03 처리 완료 후 자동 이동 (세션 상태 `REVIEW`) |
| 연결 화면 | 발송 → MTG-05 / 뒤로 → MIN-01 / Review 상태 아님 → MTG-03 / 참석자 없음 → PTC-01 |
| 하위 팝업 | MTG-04-P01 전사 원문, MTG-04-P02 검토 알림 |
| 사용 API | API-010 검토 데이터, API-001 앱 설정, API-003 참석자, API-011 화자 매핑 저장, API-012 회의록 저장, API-014 검토 확정, API-015 문서 저장·전달 시작 |
| 현행 캡처 | 없음 |

## 1. 화면 개요

자동 생성된 회의록 초안을 항목별로 고치고, 화자(Speaker A/B…)를 실제 참석자와 연결한 뒤, 문서 서비스에 저장하고 참석자에게 알린다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| MTG-04-F01 | 회의 요약 편집 | 여러 줄 입력 | - |
| MTG-04-F02 | 목록 항목 편집 | 논의 내용, 결정 사항, 후속 조치 | 항목 추가·삭제·수정. 빈 항목은 오류 |
| MTG-04-F03 | 실행 항목 편집 | 할 일, 담당자, 기한 | 할 일 필수. 담당자는 이 회의 참석자 중 선택. 기한은 올바른 날짜 |
| MTG-04-F04 | 회의록 저장 | 변경사항 저장 | 변경이 있고 유효할 때만. 서버 버전 충돌 시 최신 내용을 불러오고 수정 내용은 유지 |
| MTG-04-F05 | 화자 매핑 | 화자별로 참석자 선택 | 선택 즉시 자동 저장. 실패 시 "매핑 다시 저장" |
| MTG-04-F06 | 전사 원문 보기 | 화자·시간·발화 목록 | MTG-04-P01. 매핑한 참석자 이름으로 표시 |
| MTG-04-F07 | 문서 저장 및 참석자 알림 발송 | 검토 확정 → 문서 저장·전달 시작 | 저장 안 된 변경, 저장 중, 매핑 미저장, 문서 연결 미준비 시 MTG-04-P02로 안내하고 중단. 성공 또는 결과 불명확 시 MTG-05 이동 |
| MTG-04-F08 | 발송 대상 | 이메일·Slack 대상 결정 | 현행: 회의 참석자 전원에게 이메일, Slack은 설정에서 사용 중일 때 자동. 화면에서 선택 불가 |
| MTG-04-F09 | 재생성 진행 표시 | 다른 템플릿 재생성이 진행 중일 때 | 진행 막대 + 완료 시 최신 회의록 표시 |
| MTG-04-F10 | 이탈 방지 | 저장 안 된 변경·저장 중 | CMN-01-P01 |
| MTG-04-F11 | 다른 템플릿으로 다시 생성 | API-013 | **미연결 구현** (`MinutesRegenerationControl.tsx`). 포함 여부 D-07 |

## 3. 화면 구성 요소

### 3.1 데스크톱 (제안)

```
┌ 상단 바: ← 회의록 검토 · 주간 회의            [저장됨 ✓]  [문서 저장 및 알림 발송] ┐
│ ┌ 회의록 편집 (좌, 넓게) ──────────────────────┐ ┌ 전사 원문 (우, 고정) ──────────┐ │
│ │ 회의 요약                                  │ │ [화자 매핑]                   │ │
│ │ [                                       ]  │ │ Speaker A → [홍길동 ▾]         │ │
│ │ 논의 내용                          + 추가    │ │ Speaker B → [김철수 ▾]         │ │
│ │ [ 항목 1                         ] ×       │ │ ────────────────────────     │ │
│ │ 결정 사항                          + 추가    │ │ 홍길동 00:01                   │ │
│ │ 실행 항목                          + 추가    │ │ 이번 주 일정은...              │ │
│ │ ┌ 할 일 [            ] 담당 [▾] 기한 [  ] ×┐ │ │ 김철수 00:15                   │ │
│ │ 후속 조치                          + 추가    │ │ ...                          │ │
│ └──────────────────────────────────────────┘ └──────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 | 뒤로 가기 | 링크 | MIN-01 ("회의록 목록으로") |
| | 제목 | 제목 | 회의록 검토 (+ 회의 제목, 제안) |
| | 저장 상태 | 상태 표시 | 저장 중 / 저장됨 / 저장 안 된 변경 있음 (제안) |
| 회의록 편집 | 설명 | 텍스트 | 생성된 회의 내용을 항목별로 검토하고 수정합니다. |
| | 회의 요약 | 섹션 + 여러 줄 입력 | 접고 펼치기 |
| | 논의 내용·결정 사항·후속 조치 | 섹션 + 항목 목록 | 항목별 여러 줄 입력, × 삭제, + 추가, 빈 항목 오류 "내용을 입력해 주세요." |
| | 실행 항목 | 섹션 + 카드 목록 | 할 일(필수), 담당자 선택("담당자 선택"/참석자/"기존 담당자 유지"), 기한 날짜, × 삭제, + 추가 |
| 화자 매핑 | 설명 | 텍스트 | Speaker A/B를 실제 참석자와 연결하면 해당 이름이 전사 원문에 표시됩니다. |
| | 화자 행 | 라벨 + 선택 상자 | 화자 라벨 → 참석자 선택("참가자 선택"). 이 회의 참석자만 |
| | 전사 원문 보기 | 보조 버튼 | MTG-04-P01 (데스크톱 제안: 우측 패널로 상시 표시) |
| | 저장 메시지·매핑 다시 저장 | 상태 + 버튼 | 실패·충돌 시 |
| 실행 (하단 고정) | 회의록 변경사항 저장 | 보조 버튼 | 변경 + 유효할 때 활성 |
| | 문서 저장 및 참석자 알림 발송 | 주 버튼 | 처리 중 "문서 저장 및 참석자 알림 처리 중…" |
| | 저장 결과 다시 확인 | 보조 버튼 | 저장 결과가 불명확할 때 |

### 3.2 MTG-04-P01 전사 원문 (드로어)

| 요소 | 내용 |
|---|---|
| 제목 | 전사 원문 |
| 항목 | 화자 이름(매핑된 참석자 또는 화자 라벨), 시작 시각(mm:ss), 발화 내용 |
| 닫기 | ×, Esc, 배경 클릭. 포커스 가둠 |

### 3.3 MTG-04-P02 검토 알림

| 요소 | 내용 |
|---|---|
| 제목 | 회의록 저장 완료 / 확인 필요 |
| 본문 | 저장 완료: "회의록이 저장되었습니다." / 확인 필요: "변경된 내용이 있으니 저장하세요.", "저장 중인 변경사항이 있습니다. 저장이 끝날 때까지 기다려 주세요.", "화자 매핑을 저장한 뒤 검토를 완료해 주세요.", "문서 서비스 연결을 확인한 뒤 다시 시도해 주세요." 등 |

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)**
  - 화자 매핑이 접힌 영역에 숨어 있고, 전사 원문은 별도 드로어로만 볼 수 있어 회의록과 원문을 함께 비교하기 어렵다.
  - "회의록 변경사항 저장"과 "문서 저장 및 참석자 알림 발송" 두 버튼의 차이가 직관적이지 않다.
  - 발송 전에 누구에게 보내는지 확인할 수 없다.
  - 용어 혼용: Minutes, Review, Speaker, 참가자/참석자.
- **제안**
  - 데스크톱 2단 구성: 좌측 회의록 편집, 우측 전사 원문 + 화자 매핑
  - 자동 저장(입력 멈춘 뒤 저장) 또는 저장 상태 표시 강화 — 자동 저장은 서버 버전 충돌 처리 규칙과 함께 검토
  - 발송 전 확인 단계: 수신자(이메일)와 Slack 사용 여부를 보여 주는 확인 팝업 — `SharePage.tsx`에 수신자 선택 구현이 있어 재사용 가능 (D-07)
  - 전사 원문 검색, 발화 클릭 시 해당 위치 강조
- **확인 필요** — D-07(재생성·수신자 선택 포함 여부), 자동 저장 도입 여부
