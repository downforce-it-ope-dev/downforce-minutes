# MTG-04 회의록 검토

| 항목 | 내용 |
|---|---|
| 화면 ID | MTG-04 |
| 유형 | 페이지 (편집) |

## 1. 화면 개요

자동 생성된 회의록 초안을 항목별로 고치고, 화자(Speaker A/B…)를 실제 참석자와 연결한 뒤, 문서 서비스에 저장하고 참석자에게 알린다.

## 2. 기능 정의

| 기능 ID | 기능 | 설명 | 처리 규칙 |
|---|---|---|---|
| MTG-04-F01 | 회의 요약 편집 | 여러 줄 입력 | - |

| MTG-04-F03 | 실행 항목 편집 | 할 일, 담당자, 기한 | 할 일 필수. 담당자는 이 회의 참석자 중 선택. 기한은 올바른 날짜 |

| MTG-04-F07 | 문서 저장 및 참석자 알림 발송 | 검토 확정 → 문서 저장·전달 시작 | 저장 안 된 변경, 저장 중, 매핑 미저장, 문서 연결 미준비 시 MTG-04-P02로 안내하고 중단. 성공 또는 결과 불명확 시 MTG-05 이동 |

## 3. 화면 구성 요소

### 3.1 태블릿 (기준, 폭 600px 이상)

화면 기준은 마이크가 있는 태블릿 세로(폭 820px 전후)다. 공통 틀(내비게이션 레일 88px, 상단 바 64px)은 CMN-01을 따르고, 크기·글자·색 수치는 [스타일 방식 검토](../스타일_전환_검토.md) 7.4·8장을 따른다. 세로 화면은 1단으로 편집하고, 전사 원문은 오른쪽에서 열리는 시트(MTG-04-P01)로 본다.

```
┌──────┬──────────────────────────────────────────────┐
│ [로고]│ ← 회의록 검토 · 주간 회의  [저장됨 ✓] [전사 원문] │  상단 바 64px
│      ├──────────────────────────────────────────────┤
│  ⌂   │ ┌ 화자 매핑 ─────────────────────────────┐   │
│  홈   │ │ Speaker A    [홍길동               ▾]  │   │  행 60px
│  ▤   │ │ Speaker B    [김철수               ▾]  │   │
│ 회의록 │ └────────────────────────────────────────┘   │
│  👥  │ 회의 요약                              [접기]  │
│ 참석자 │ [ 여러 줄 입력 (내용만큼 높이 늘어남)       ]  │
│  ⚙   │ 논의 내용                            [+ 추가]  │
│  설정  │ [ 항목 1                              ] [×]  │
│      │ 결정 사항                            [+ 추가]  │
│      │ 실행 항목                            [+ 추가]  │
│      │ ┌ 할 일 [                          ]   [×] ┐   │
│      │ │ 담당 [홍길동     ▾]  기한 [2026-11-12  ]  │   │
│      │ └────────────────────────────────────────┘   │
│      │ 후속 조치                            [+ 추가]  │
│      ├──────────────────────────────────────────────┤
│  [👤] │ [변경사항 저장]   [문서 저장 및 참석자 알림 발송] │  하단 실행 바 (고정)
└──────┴──────────────────────────────────────────────┘
 레일 88px
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 상단 바 (높이 64px) | 뒤로 가기 | 아이콘 버튼 48×48 | MIN-01 ("회의록 목록으로") |
| | 제목 | 제목(h1) | 회의록 검토 (+ 회의 제목, 제안). `headline`, 길면 한 줄 말줄임 |
| | 저장 상태 | 상태 표시 | 저장 중 / 저장됨 / 저장 안 된 변경 있음 (제안). 아이콘 + 문구(`caption`)로 표시하고 색만으로 구분하지 않는다. 저장됨 `text-muted`, 저장 안 된 변경 `warning-soft`, 저장 실패 `danger-soft` |
| | 전사 원문 | 보조 버튼 `md` 48 | MTG-04-P01 열기 (세로 화면). 가로 화면(960px 이상)에서는 오른쪽 패널에 상시 표시하므로 숨긴다 |
| | 새 회의 (CMN-01 공통) | 주 버튼 | 이 화면에서는 숨기는 것을 제안한다. 하단 "문서 저장 및 참석자 알림 발송"과 주 버튼이 둘이 되기 때문이다. **확인 필요**: CMN-01 상단 바 "새 회의" 숨김 화면(현재 녹음·처리 화면)에 이 화면을 추가할지 |
| 화자 매핑 (편집 영역 위, 카드) | 설명 | 텍스트 | Speaker A/B를 실제 참석자와 연결하면 해당 이름이 전사 원문에 표시됩니다. (`caption`, `text-muted`) |
| | 화자 행 | 라벨 + 선택 상자 | 화자 라벨(`label`) → 참석자 선택("참가자 선택"). 이 회의 참석자만. 행 1줄 60px, 선택 상자 높이 52px·글자 16px. 휴대폰에서 선택 상자를 누르면 하단 시트 목록으로 고른다(제안) |
| | 저장 메시지·매핑 다시 저장 | 상태 + 버튼 | 실패·충돌 시. `danger-soft` 안내 + 보조 버튼 `md` 48 |
| | 카드 | 영역 | 테두리 `border`, 모서리 `radius-lg` 16, 안쪽 여백 24(휴대폰 16). 현행은 접힌 영역이며, 리뉴얼은 펼쳐서 편집 영역 위에 둔다(제안) |
| 회의록 편집 | 설명 | 텍스트 | 생성된 회의 내용을 항목별로 검토하고 수정합니다. (`caption`, `text-muted`) |
| | 섹션 제목 | 제목(h2) | `title`. 오른쪽에 "+ 추가" 보조 버튼 `sm` 40(누르는 영역 48) |
| | 회의 요약 | 섹션 + 여러 줄 입력 | 접고 펼치기(접기 버튼은 항상 보이는 아이콘 버튼 48×48). 입력 글자 `body` 16px(16px 미만이면 iPad·iPhone이 자동 확대). 입력란은 내용만큼 높이가 늘어난다(제안). 최소 높이는 **확인 필요**(제안: 3줄 분량) |
| | 논의 내용·결정 사항·후속 조치 | 섹션 + 항목 목록 | 항목별 여러 줄 입력(최소 높이 52px, 내용만큼 늘어남), 삭제 ×는 항상 보이는 아이콘 버튼 48×48(hover로만 나타나지 않음), + 추가, 빈 항목 오류 "내용을 입력해 주세요."(입력란 아래 `caption`, red-700 글자 + 오류 아이콘, 입력란 테두리 `danger`) |
| | 실행 항목 | 섹션 + 카드 목록 | 할 일(필수), 담당자 선택("담당자 선택"/참석자/"기존 담당자 유지"), 기한 날짜, × 삭제, + 추가. 태블릿 세로: 1행 할 일 + ×, 2행 담당·기한 2칸. 입력란 높이 52px, 카드 사이 12px |
| | 항목 사이 간격 | 간격 | 요소 사이 8/12/16, 구역 사이 32(휴대폰 24) |
| 실행 (하단 고정 바) | 회의록 변경사항 저장 | 보조 버튼 `md` 48 (`primary-soft`) | 변경 + 유효할 때 활성 |
| | 문서 저장 및 참석자 알림 발송 | 주 버튼 `lg` 56 (`primary`) | 처리 중 "문서 저장 및 참석자 알림 처리 중…" |
| | 저장 결과 다시 확인 | 보조 버튼 `md` 48 | 저장 결과가 불명확할 때 |
| | 고정 바 | 영역 | 흰 배경 + 위쪽 구분선 `border`, 하단 안전 영역만큼 띄운다. 편집 영역 끝에 고정 바 높이만큼 여백을 두어 마지막 입력란이 가려지지 않게 한다. 바 높이는 버튼 56 + 위아래 여백으로 정해지며 고정값은 **확인 필요**(제안: 위아래 12px) |

- **터치 키보드 편집 (태블릿)**
  - 세로 화면은 화면 키보드가 열려도 남은 높이가 560px보다 커서 `short`에 걸리지 않는다. 하단 실행 바는 유지하되, 초점이 간 입력란이 키보드나 실행 바에 가리지 않도록 화면을 스크롤한다.
  - iPad Safari에서 키보드가 열린 상태의 고정 요소 위치는 기기마다 다를 수 있어 **확인 필요**하다(Safari 자동 테스트 제외, S-08).
  - 긴 글은 입력란 안에서 따로 스크롤하지 않고 입력란 높이를 늘려 페이지 스크롤 하나로 읽고 고치게 한다(제안).

### 3.2 태블릿 가로 (폭 960px 이상)

회의록 편집과 전사 원문을 함께 비교할 수 있도록 2단으로 나눈다(8.2 `tablet-lg`에서 2단을 허용하는 대표 화면).

```
┌──────┬──────────────────────────────────────────────────────────────────┐
│ [로고]│ ← 회의록 검토 · 주간 회의                              [저장됨 ✓]   │  상단 바 64px
│      ├────────────────────────────────────┬─────────────────────────────┤
│  ⌂   │ 회의록 편집 (넓게, 따로 스크롤)        │ 화자 매핑               [접기] │
│  홈   │ 회의 요약                            │ Speaker A → [홍길동      ▾]  │
│  ▤   │ [                                ] │ Speaker B → [김철수      ▾]  │
│ 회의록 │ 논의 내용                   [+ 추가] │ ───────────────────────────  │
│  👥  │ [ 항목 1                      ] [×] │ 전사 원문 (따로 스크롤)         │
│ 참석자 │ 결정 사항                   [+ 추가] │ 홍길동  00:01                 │
│  ⚙   │ 실행 항목                   [+ 추가] │ 이번 주 일정은...              │
│  설정  │ ┌ 할 일 [                 ]  [×] ┐ │ 김철수  00:15                 │
│      │ │ 담당 [▾]       기한 [        ]  │ │ ...                         │
│      │ └──────────────────────────────┘ │                             │
│      ├────────────────────────────────────┤                             │
│  [👤] │ [변경사항 저장] [문서 저장 및 알림 발송] │                             │
└──────┴────────────────────────────────────┴─────────────────────────────┘
 레일 88px            왼쪽: 편집                    오른쪽 패널: 매핑 + 원문
```

| 영역 | 요소 | 유형 | 내용·규칙 |
|---|---|---|---|
| 왼쪽 단 | 회의록 편집 | 영역 | 3.1 편집 영역과 같다. 하단 실행 바는 왼쪽 단 아래에 고정한다 |
| 오른쪽 패널 | 화자 매핑 | 카드 | 3.1 화자 매핑과 같다. 접고 펼칠 수 있다(아이콘 버튼 48×48) |
| | 전사 원문 | 목록 | MTG-04-P01과 같은 내용을 패널에 상시 표시한다. 발화 글자 `body-lg`(18/30), 화자 이름 `label`, 시각 `caption` 고정폭 숫자 |
| | 패널 폭 | 배치 | 384px 고정, 나머지를 편집 단에 배정 (스타일 방식 검토 8.6 보조 크기) |
| 공통 | 스크롤 | 규칙 | 두 단은 각각 따로 스크롤한다. 상단 바와 하단 실행 바는 고정 |

### 3.3 휴대폰 (폭 600px 미만)

- **배치:** 1단. 상단 바(높이 56px)에 뒤로 가기, 제목(한 줄 말줄임), 저장 상태 아이콘, 전사 원문 아이콘 버튼(48×48)을 둔다. 하단 탭 바는 CMN-01을 따른다.
- **화자 매핑:** 편집 영역 위 카드로 둔다. 화자 행은 화자 라벨과 선택 상자를 위아래 2줄로 쌓는다(선택 상자 높이 48px, 글자 16px). 선택 목록은 하단 시트로 연다(제안).
- **실행 항목 카드:** 할 일, 담당, 기한을 한 줄에 하나씩 쌓는다. 삭제 ×는 카드 오른쪽 위 아이콘 버튼 48×48.
- **전사 원문:** MTG-04-P01을 화면 전체를 덮는 시트로 연다. 상단에 제목과 닫기, 발화는 `body-lg`(17/28).
- **하단 실행:** "문서 저장 및 참석자 알림 발송"은 주 버튼 `lg` 56으로 하단 탭 바 위에 화면 폭 가득 고정하고, 하단 안전 영역만큼 띄운다. "회의록 변경사항 저장"은 같은 고정 영역 안에 보조 버튼으로 두면 고정 영역이 커져 편집 공간이 줄어든다. **확인 필요**(제안: 주 버튼 왼쪽에 보조 버튼 `md` 48을 나란히 두거나, 상단 바 저장 상태 옆으로 옮김).
- **대화상자:** MTG-04-P02와 발송 전 확인(제안)은 하단 시트(폭 가득, 최대 높이 90%, 모서리 `radius-xl` 20)로 연다.
- **키보드가 열린 상태(`short`, 높이 560px 이하):** 상단 바와 여백을 줄이고, 하단 고정 실행 바는 본문 끝으로 옮긴다. 저장 상태는 상단 바에 계속 표시해, 키보드를 닫지 않아도 저장 여부를 알 수 있게 한다.
- **보이는 양:** 휴대폰 세로(360×780 기준)는 키보드가 열리면 입력란 1~2개만 보인다(추정). 긴 요약은 입력란 높이를 늘려 페이지 스크롤로 고친다.

## 5. 리뉴얼 검토 사항

- **현행 문제 (관찰)**
  - 화자 매핑이 접힌 영역에 숨어 있고, 전사 원문은 별도 드로어로만 볼 수 있어 회의록과 원문을 함께 비교하기 어렵다.
  - "회의록 변경사항 저장"과 "문서 저장 및 참석자 알림 발송" 두 버튼의 차이가 직관적이지 않다.
  - 발송 전에 누구에게 보내는지 확인할 수 없다.
  - 용어 혼용: Minutes, Review, Speaker, 참가자/참석자.
- **제안**
  - 태블릿 가로(960px 이상) 2단 구성: 왼쪽 회의록 편집, 오른쪽 전사 원문 + 화자 매핑. 태블릿 세로·휴대폰은 1단 + 전사 원문 시트(3.1~3.3)
  - 자동 저장(입력 멈춘 뒤 저장) 또는 저장 상태 표시 강화 — 자동 저장은 서버 버전 충돌 처리 규칙과 함께 검토
  - (D-07 결정으로 제외) 발송 전 수신자 선택 확인 팝업
  - 전사 원문 검색, 발화 클릭 시 해당 위치 강조
- **확인 필요** — D-07(재생성·수신자 선택 포함 여부), 자동 저장 도입 여부, 오른쪽 패널·시트 폭, 휴대폰에서 "회의록 변경사항 저장" 버튼 위치, 이 화면의 상단 바 "새 회의" 버튼 숨김 여부. D-06(지원 화면 크기)은 태블릿 기준으로 결정됨
- **화면 크기 관련 메모** — 자동 저장을 도입하면 "회의록 변경사항 저장" 버튼이 빠져 휴대폰 하단 고정 영역 문제가 함께 해결된다.
