## 1. 결론

- 현재 CSS를 Tailwind로 1:1 옮기지 않는다. 화면을 리뉴얼하거나 새로 만들 때 화면 기획 문서를 기준으로 Tailwind로 작성한다.
- 전환 기간에는 프로젝트 안에 두 방식이 함께 존재한다. 대신 **한 화면 안에서는 한 가지 방식만** 쓴다.
- 기존 CSS는 우선순위가 낮은 영역에 가두어 리뉴얼 화면에 영향을 주지 못하게 한다.
- 화면 리뉴얼이 끝날 때마다 그 화면의 기존 CSS를 지운다.

## 3. 검토한 방식

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 직접 작성한 CSS 유지 (디자인 토큰만 정리) | 새 도구 도입 없음 | 체계 없는 값과 화면 구조 의존을 계속 안고 감 | 채택 안 함 |
| B. 현재 CSS를 Tailwind로 1:1 변환 | 화면 모양 유지 | 임의값 클래스로 채워져 Tailwind 장점이 없음. 사실상 재작성. 리뉴얼에서 버릴 화면에 하는 작업 | 채택 안 함 |
| C-1. Tailwind 도입 + 별도 브랜치에서 전체 화면 일괄 전환 | 두 방식이 `main`에 공존하지 않음 | 전환이 끝날 때까지 `main`에 화면 개선을 반영할 수 없고 브랜치가 오래 유지됨 | 채택 안 함 (변경) |
| **C-2. Tailwind 도입 + 리뉴얼하는 화면부터 전환** | 리뉴얼 일정에 맞춰 화면별로 반영 가능. 화면 전체를 한 번에 고치지 않아도 됨 | 전환 기간에 두 방식이 공존하므로 격리 규칙이 필요 (4장) | **채택** |

## 4. 화면 단위 전환 시 위험과 대응

### 4.1 기존 전역 규칙이 리뉴얼 화면을 덮어씀 (높음)

- **현상**
  - `base.css`의 `:root` 글꼴·색, `button:disabled { opacity: .6 }`, `:focus-visible` 외곽선, `* { scrollbar-width: none }` 같은 규칙은 모든 요소에 적용된다.
  - Tailwind 유틸리티는 cascade layer 안에 들어간다. 그래서 layer 밖의 기존 CSS가 선택자 우선순위와 무관하게 항상 이긴다. 예를 들어 리뉴얼 화면의 `disabled:opacity-40`은 기존 `button:disabled`에 덮어써진다.
- **대응**
  - 기존 CSS 전체를 `@layer legacy`로 감싸 Tailwind 유틸리티보다 낮은 우선순위에 둔다. layer 순서 예: `theme, base, legacy, components, utilities`.
  - 전역 규칙 중 리뉴얼 화면에도 필요한 것(글꼴, 포커스 표시 등)은 Tailwind 토큰과 기본 스타일로 다시 정의한다.

### 4.2 Tailwind 기본 초기화(Preflight)가 기존 화면을 바꿈 (높음)

- **현상**
  - Tailwind는 제목 여백, 목록 점, 이미지 표시 방식, 테두리 기본값 등을 초기화한다.
  - 기존 CSS가 직접 지정하지 않은 속성은 이 초기화 값으로 바뀌어, 리뉴얼하지 않은 화면 모양이 달라질 수 있다.
- **대응**
  - Tailwind 도입 작업(0단계)에서 CSS 분리 때와 같은 화면 캡처·계산 스타일 비교로 기존 화면 변화를 확인한다.
  - 차이가 나면 기존 화면에 필요한 값을 `legacy` layer에 보완한다.
  - 초기화를 끄는 방법도 있지만, 그러면 리뉴얼 화면의 기본값이 흔들리므로 권장하지 않는다.

### 4.3 공통 레이아웃(앱 틀) 공유 (높음)

- **현상**
  - 모든 화면은 `App.tsx`의 앱 틀(머리글, 하단 메뉴, `app-shell`, `page-scroll-layout`) 안에 그려진다.
  - 리뉴얼 레이아웃(CMN-01: 태블릿 내비게이션 레일, 휴대폰 하단 탭 바)은 앱 틀 자체를 바꾼다. 기존 화면 CSS는 현재 앱 틀의 높이 계산(`calc(100vh - 74px)` 등)에 의존한다.
- **대응**
  - 라우트별로 레이아웃을 고르게 한다. 리뉴얼 화면은 새 레이아웃, 기존 화면은 기존 레이아웃을 쓴다.
  - 새 레이아웃(CMN-01)을 첫 리뉴얼 대상으로 삼는다.
  - 전환 기간에는 화면을 옮겨 다닐 때 레이아웃이 바뀌어 보인다. 사용자에게 공개하는 시점과 범위를 정해야 한다(S-05).

### 4.4 공유 컴포넌트 (중간)

- **현상**
  - 토스트, 비동기 상태 카드(`AsyncState`), 서버 연결 복구 화면, 이동 확인, 참석자 선택은 여러 화면이 함께 쓴다.
  - 리뉴얼 화면이 이 컴포넌트를 그대로 쓰면 한 화면에 두 방식이 섞인다.
- **대응**
  - 리뉴얼 화면은 Tailwind로 만든 새 컴포넌트를 쓴다.
  - 기존 컴포넌트는 기존 화면이 모두 리뉴얼될 때 삭제한다.
  - 전역으로 뜨는 서버 연결 복구 화면(CMN-02)은 새 레이아웃과 함께 먼저 리뉴얼한다.

### 4.5 사용자가 보는 화면 일관성 (중간)

- 전환 기간에는 리뉴얼 화면과 기존 화면의 디자인이 다르다.
- 화면 묶음 단위(예: 회의 진행 흐름 MTG-01~05)로 리뉴얼하고 배포하면 한 흐름 안에서 디자인이 바뀌는 일을 줄일 수 있다.

### 4.6 규칙 위반을 사람이 놓침 (중간)

- `CLAUDE.md` 지침은 Claude 작업에만 적용된다. 사람이 작업할 때는 강제되지 않는다.
- 0단계에서 lint 검사를 추가할 것을 권장한다.
  - 새 CSS 파일 생성 금지
  - 리뉴얼 화면에서 기존 클래스 사용 금지
  - 임의값 클래스 금지
  - `frontend/src/styles/` 변경 시 경고

### 4.7 기존 CSS 정리 누락 (낮음)

- 화면을 리뉴얼한 뒤 기존 CSS를 지우지 않으면 쓰이지 않는 규칙이 남는다.
- 화면 리뉴얼 작업의 완료 기준에 "해당 `pages/*.css` 삭제"와 "미사용 클래스 검사"를 넣는다.

### 4.8 현재 CSS 분리의 분류 오류 (낮음, 확인됨)

- 2026-11-06 CSS 분리 작업에서 참석자 화면 규칙 일부(`.participants-page`, `.participants-main`, `.participants-heading-icon`, `.participants-create-dock`)와 회의 필터 규칙(`.meeting-filters`)이 `base.css`에 잘못 분류되었다.
- 화면 모양은 분리 전과 같다(캡처 비교 확인). 해당 화면을 리뉴얼해 지울 때 `base.css`에서도 함께 지워야 한다.
- 지금 옮기려면 적용 순서가 바뀌므로 다시 화면 비교가 필요하다.

### 7.3 토큰 적용 원칙 (1차)

- **CI 원색의 용도:** CI 3색은 브랜드 표시, 배경 면, 강조 영역, 일러스트, 상태 배지 배경처럼 대비 기준이 낮아도 되는 곳에 쓴다.
- **CI 원색 위의 글자:** CI 원색 면 위의 글자는 진한 글자색을 쓴다. 대비 6.72:1 이상으로 AA를 충족한다.
- **파생 색 (승인 필요):**
  - 글자, 링크, 흰 글자 버튼, 입력 테두리, 포커스 표시에는 CI 색과 같은 색상 계열의 진한 파생 색을 쓴다.
  - 파생 색 값은 0단계에서 정한다. CI 문서에 없는 색이므로 회사 승인 필요 여부를 확인한다.
- **기존 서비스 색:** 남색 `#0b2d5b`, 파랑 `#3b82f6`, 청록 `#14b8a6`은 리뉴얼 토큰에 쓰지 않는다.
- **로고 교체 (결정):** 현재 "Windsoft Minutes" 이름·로고를 다운포스 CI로 바꾼다. 서비스 표기는 "Downforce Minutes"(1차)이며 [화면 목록](화면기획/00_화면목록.md) D-10에 기록했다.

### 7.4 기본 컬러 (1차 안, 2026-11-06)

CI Color System 3색과 흰 배경을 조합한 기본 컬러다.
- **만든 방법:** CI 색의 색상(hue)을 유지한 채 밝기만 바꿔 50~900 단계를 만들었다(OKLCH 색 공간 기준).

### 8.2 화면 폭 기준 (Breakpoint)

Tailwind 기본 기준(`sm`·`md`·`lg`·`xl`·`2xl`)은 지우고(`--breakpoint-*: initial;`) 아래 2개만 쓴다. 작은 화면(휴대폰)이 기본값이다.

| 이름 | 조건 | 대상 | 배치 |
|---|---|---|---|
| (기본) | 폭 600px 미만 | 휴대폰 세로 | 1단, 하단 탭 바 |
| `tablet` | 폭 600px 이상 | 태블릿 세로, 작은 태블릿 | 1단, 왼쪽 내비게이션 레일 |
| `tablet-lg` | 폭 960px 이상 | 태블릿 가로 | 필요한 화면만 2단 (예: 회의록 검토 + 전사 원문), 왼쪽 내비게이션 레일 |
| `short` (높이 조건) | 높이 560px 이하 | 휴대폰 가로, 화면 키보드가 열린 상태 | 상단 바·여백 축소, 고정 하단 버튼은 본문 끝으로 이동 |

- 600px은 Android가 태블릿 배치를 시작하는 기준(smallest width 600dp)과 같다.
- 960px은 태블릿 가로 폭(1024~1366px)을 모두 포함하고, 태블릿 세로 폭(744~834px)은 포함하지 않는다.
- 휴대폰 가로(예: 844×390)는 폭만 보면 `tablet`에 걸린다. 그래서 `short` 높이 조건으로 따로 줄인다. 휴대폰 가로는 동작은 보장하되 최적화는 하지 않는다.
- 본문 최대 폭은 1040px이다. 그보다 넓은 화면(PC)에서는 가운데 정렬한다.

| `headline` | 24/32 | 28/36 | 700 | 페이지 제목 (h1) |
| `title` | 18/26 | 20/28 | 600 | 구역·카드 제목 (h2·h3) |
| `body-lg` | 17/28 | 18/30 | 400 | 회의록·전사 원문 읽기 영역 |
| `body` | 16/24 | 16/24 | 400 | 기본 본문, 입력값 |
| `label` | 15/22 | 16/24 | 600 | 버튼, 입력 이름표, 탭 |
| `caption` | 13/18 | 14/20 | 400 | 날짜·메타 정보, 도움말, 오류 문구 |
| `nav` | 12/16 | 13/18 | 600 | 하단 탭 바·내비게이션 레일 이름 |

- **비율 원칙**
  - 본문(`body`) 16px은 두 기기에서 같다.
  - 제목과 숫자 표시는 태블릿에서 약 1.1~1.3배 키운다. 태블릿은 책상에 두고 조금 떨어져 보는 경우가 많기 때문이다.
- **입력란 글자 크기:** 16px 미만으로 하지 않는다. iPhone·iPad Safari는 16px 미만 입력란에 초점이 가면 화면을 자동 확대한다.
- **최소 글자 크기:** `nav` 12px이 최소다. 일반 글자는 13px 미만으로 쓰지 않는다.
- **글꼴: Pretendard Variable (결정, S-07)**
  - CI에 지정 서체가 없어 가독성을 기준으로 골랐다.
    - 한글과 영문·숫자가 한 글꼴 안에서 크기와 굵기가 고르게 맞는다. 회의록처럼 영문 고유명사·숫자가 섞인 글에서 줄이 들쭉날쭉하지 않다.
    - 글자 내부 공간이 넓고 획이 단순해 작은 크기(13~14px)와 태블릿을 떨어져 볼 때도 형태가 뚜렷하다.
    - 숫자를 같은 폭으로 표시하는 기능(`tabular-nums`)을 지원한다.
    - 한 파일에서 굵기를 자유롭게 고를 수 있는 가변 글꼴(Variable)이다.
  - 쓰는 굵기는 400(본문), 600(이름표·버튼·소제목), 700(페이지 제목) 세 가지로 제한한다.
  - 자간
    - 제목(`headline`·`display`)은 -0.02em, `title`은 -0.01em으로 약간 좁힌다.
    - 본문 이하는 0으로 둔다. 한글 본문 자간을 좁히면 작은 글자에서 가독성이 떨어진다.
  - 숫자 표시
    - 녹음 시간, 진행률, 날짜·시간은 고정폭 숫자(`tabular-nums`)로 표시해 값이 바뀔 때 글자가 흔들리지 않게 한다.
  - 대체 글꼴 순서: `Pretendard Variable`, `Pretendard`, `-apple-system`, `system-ui`, `Apple SD Gothic Neo`, `Noto Sans KR`, `sans-serif`.
  - 글꼴 파일은 패키지로 설치해 직접 제공한다. 외부 CDN 장애나 사내망 차단에 영향받지 않게 하기 위해서다.

### 8.7 태블릿·휴대폰 우선에 따른 확인 사항

- **Safari 브라우저 테스트: 제외 (결정, S-08)**
  - 자동 브라우저 테스트는 Chromium만 쓴다.
  - Safari(WebKit) 테스트는 필요할 때 추가한다.
- **녹음 형식**
  - Safari는 녹음을 `audio/mp4`로 만든다.
  - Backend 기본 설정은 `audio/webm`과 `audio/mp4`를 모두 받는다(`ACCEPTED_AUDIO_MIME_TYPES` 기본값, `MeetingSessionService.java`).
  - 운영 서버(GCE)의 실제 설정값은 확인하지 못했다.
- **화면 꺼짐**
  - 태블릿을 세워 두고 긴 회의를 녹음하면 화면이 꺼지면서 녹음이 멈출 수 있다.
  - 녹음 화면(MTG-02)의 화면 꺼짐 방지 처리는 해당 화면 리뉴얼 때 확인한다.
- **화면 방향:** 태블릿은 세로·가로 모두 지원한다. 휴대폰은 세로를 기준으로 하고, 가로는 동작만 보장한다(8.2).
